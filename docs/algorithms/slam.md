## 2. slam_toolbox — 원리와 파라미터 근거

**스캔 매칭 (프런트엔드).** 새 스캔을 odom 예측 자세 주변 상관 탐색 창(±`correlation_search_space_dimension`/2,
coarse 2 × 0.01 m 간격, 각도 coarse ±0.349 rad 를 0.0349 rad 간격)에서 스미어된 점유 격자와의 응답
(끝점이 점유 셀에 떨어지는 비율)을 최대화하는 자세로 정하고, 그 주변 ±½·coarse 각 간격(±1°)을
`fine_search_angle_offset` 간격, ±0.01 m 를 0.01 m 간격으로 다시 훑는다. odom 에서 멀어질수록
`distance/angle_variance_penalty` 로 응답에 벌점을 곱하고, 응답 곡면의 2차 모멘트로 매칭 공분산 Σ 를 낸다.
이동이 `minimum_travel_distance/heading` 을 넘을 때마다 포즈 그래프에 노드(스캔)와 간선(상대 자세, Σ)을 추가한다.

**루프 폐합 탐지·검증.** 현재 체인 밖 노드 중 `loop_search_maximum_distance` 이내이고 체인 길이가
`loop_match_minimum_chain_size` 이상인 후보에 대해 `loop_search_space_dimension`(8 m) 조대 매칭 →
`response_coarse > loop_match_minimum_response_coarse` ∧ `Σ_xx, Σ_yy < loop_match_maximum_variance_coarse` →
순차 매처로 정밀 매칭 `response_fine ≥ loop_match_minimum_response_fine` 이면 루프 간선 추가 (아니면 기각).

**그래프 최적화 (백엔드, Ceres).** 노드 자세 (p_i, θ_i), 간선 측정 (p̂_ij, θ̂_ij, Ω_ij = Σ_ij⁻¹):

```
e_ij = [ R(θ_i)ᵀ (p_j − p_i) − p̂_ij ;  wrap(θ_j − θ_i − θ̂_ij) ]
min Σ ρ_H( e_ijᵀ Ω_ij e_ij ),   ρ_H = Huber (a = 0.7) — 잘못 수락된 루프 간선의 영향을 선형 벌점으로 제한
```

Levenberg–Marquardt + 희소 정규방정식(`SPARSE_NORMAL_CHOLESKY`)으로 푼다. 루프가 닫히면 체인 전체가
재배치되어 누적 드리프트가 루프 둘레에 분산된다.

| 파라미터 | 기본 | 설정 | 근거 |
| --- | --- | --- | --- |
| `resolution` | 0.05 | **0.05** | 명세 ≤ 0.05 m |
| `max_laser_range` | 20 | 25 | LiDAR 사양, 60 m 창고의 긴 통로 끝 벽까지 래스터화 |
| `minimum_travel_distance / heading` | 0.5 / 0.5 | 0.3 / 0.3 | 노드 밀도 ↑ → 좁은 랙 통로에서 국소 정합·루프 후보 ↑ |
| `correlation_search_space_dimension` | 0.5 | 0.5 | ±0.25 m 창: 0.3 m 이동 간 odom(EKF) 오차 ≪ 0.25 m |
| `correlation_search_space_smear_deviation` | 0.1 | 0.05 | ≈ σ_lidar(0.03) + res. 크면 벽이 두꺼워짐 |
| `fine_search_angle_offset` | 0.00349 | **0.00087** | 이름과 달리 정밀 탐색의 **각 간격**. 0.2° 면 노드 헤딩이 ±0.1° 로 양자화 → 10 m 앞 벽 ±1.7 cm. 0.05° (정밀 각 41 개, 매칭 비용 ~4 배) 로 바꿔 다시 만든 지도에서 잔여 회전 −0.099° → −0.029°, 재현율 0.52 → 0.74 (§6.1, 같은 경로·같은 평가기) |
| `loop_search_maximum_distance` | 3.0 | 5.0 | 100 m 루프의 0.05~1 % 드리프트(≤ 1 m)를 넉넉히 포함 |
| `loop_match_minimum_chain_size` | 10 | 15 | 반복 랙 통로(겉보기 같은 곳) aliasing 오수락 억제 |
| `loop_match_minimum_response_fine` | 0.45 | 0.55 | 같은 이유 |
| `ceres_loss_function` | None | HuberLoss | 오수락 루프의 영향 제한 |
| `map_update_interval` | 5 | 2 | 매핑 중 커버리지 확인 편의 |

명세 힌트("지도가 찌그러지면 chain_size, correlation_search_space 조정") 해석: 찌그러짐 = 오수락 루프
(체인·응답 임계 ↑) 또는 국소 매칭 실패(탐색 창·스미어 ↑).

## 3. 맵 품질 지표 (명세 "맵 일관성, 구조물 정확도")

지면 진실 M_gt: 월드 SDF 의 정적 모델 visual 을 **LiDAR 스캔 평면 높이**에서 자른 단면을 0.05 m 로 래스터화
(`world_to_map`; gpu_lidar 는 visual 을 측정하므로 visual 을 쓴다; 지게차·작업자·로봇은 제외). 높이는 설정 단일 출처에서
계산한다: `robot_params.yaml base_link_height` 0.18 + `sensors.yaml lidar.extrinsic.z` 0.02 = **0.20 m** (차체 안 슬롯
LiDAR; `world_geometry.scan_plane_height`). map 프레임 = 월드 프레임이므로 먼저 그대로 비교(ADNN_0)하고, 점유 셀을 GT
거리장에 맞추는 SE(2) 최소제곱(soft-L1)으로 잔여 정렬을 구한다 (정렬량이 곧 map↔월드 어긋남). `map_quality` CLI 가

**면 위치 추정과 띠 규약.** SLAM(Karto) 격자는 면을 두께 2.7~2.9 셀 띠로 그린다 (§6.1). 이전 추정(구간마다 가장 안쪽
점유 셀 + 반 셀)은 잡음이 띠를 두껍게 할수록 면을 방 안쪽으로 옮겨 "맵이 0.16~0.36 % 작다" 는 결론을 냈다 — 이는
추정기 편향이었다 (리뷰; `test_wall_face_estimator_is_stable_under_band_thickness`: 두께 1 → 5 셀에서 이전 추정은 간격을
10 cm 줄이고, 중앙값 추정은 변하지 않는다). 중앙값도 **실제 면과 같지는 않다**: Karto 는 셀마다 적중/통과 수 비가
`occupancy_threshold` 0.1 을 넘으면 점유로 두므로, 광선이 드물게 지나는 면 뒤 셀은 적중만으로 점유가 되고 면 앞 셀은
통과가 많아 비가 낮다. 1D 모델(끝점 N(면, σ), 셀 0.05 m)에서 완전한 지도의 띠 중앙값은 면 **뒤** +0.7~+3.4 cm
(σ_eff 0.03~0.05 m, 광선 50~400 개)라 외벽 간격은 완전한 지도에서도 +1.4~+6.8 cm 로 읽힌다. 그래서 축척은 기둥 중심 간
거리(규약 상쇄)로 판정하고, 외벽 간격은 그 규약 차를 알고 읽는다.

**CI 회귀 시험** (`test_map_world.py`, 커밋된 `maps/warehouse.*` 대상): YAML 계약(해상도 ≤ 0.05, 원점 yaw 0, 미지가 미지로
읽힘), 관측 불가 셀(기둥·랙 속, 벽 밖)이 자유로 읽히지 않음, **알려진 구조물 면이 월드 좌표 그대로 점유** (기둥 32 면·랙 통로면

## 4. AMCL — 모델과 튜닝 근거 (`config/amcl.yaml`)

- **운동 모델** (DifferentialMotionModel): `δ̂ = δ − N(0, α₁δ_rot² + α₂δ_trans²)` 등. α 는 **분산 계수**.
  입력 odom 이 EKF(휠+자이로) 출력이라 raw odom 전제의 기본 0.2 (σ 45 %) 는 과대 → 갱신마다 구름이 σ_hit 보다
  넓게 퍼져 가중치가 붕괴한다. 물리값(병진 σ ≈ 0.7 %)에 파티클 다양성 팽창 κ ≈ 6 → α ≈ 2e-3~5e-3.
- **관측 모델** (likelihood field): `p = z_hit exp(−d²/2σ_hit²) + z_rand/z_max`, 가중치 `1 + Σ p³`.
  `σ_hit ≈ sqrt(σ_lidar² + res²/12 + σ_map²) ≈ 0.05` 에 맵 오차 여유를 두어 0.08. z_hit 0.8 / z_rand 0.2
  (동적 장애물 흡수), `max_beams` 180 (60 은 좁은 통로 벽 정보 부족), `laser_likelihood_max_dist` 2.0.
- **파티클**: min 500 / max 8000, KLD (`pf_err` 0.05, `pf_z` 0.99). nav2 humble 리샘플러는 O(N²) 선형 탐색 →
  8000 개가 상한. 추적 중 KLD 가 수백 개로 줄인다.
- **리샘플링**: `resample_interval` 1. Augmented MCL 주입은 **끈다** (`recovery_alpha_slow` = `recovery_alpha_fast` = 0):
  켰을 때 주행 중(원호·동적 장애물 가림) 주입으로 AMCL 공분산이 수 초간 부풀어 kidnap_monitor 가 거짓 LOST 를 냈다
  (이전 기반 관측, amcl.yaml 주석). 납치 복구는 kidnap_monitor 의 결정적 전역 가설 탐색 + 회전 + (최후)
  `reinitialize_global_localization` 이 맡는다 (§5).
- **갱신 조건**: `update_min_d` 0.10 m, `update_min_a` 0.08 rad (1 rad/s × 10 Hz 회전에서 스캔당 0.1 rad 가
  엄격 부등호 0.1 에 걸려 갱신이 누락되지 않도록).
- **정지 직후 무이동 갱신** (`kidnap_monitor_node` 의 `StopUpdateScheduler`): AMCL 은 움직일 때만 갱신하므로
  정지하면 마지막 주행 중 갱신의 오차가 그대로 굳는다. 움직이다 `|v| < 0.01 m/s`, `|ω| < 0.01 rad/s` 가 0.5 s 지속되면
  `request_nomotion_update` 를 1 s 간격 3 회 호출해 같은 자세의 스캔으로 파티클을 다시 모은다. 무이동 갱신은 운동 잡음
  없이 리샘플하므로 반복하면 파티클이 고갈된다 → 정지당 3 회로 제한 (brief §2.4, `nomotion_updates_on_stop`).

### 4.1 nav2_amcl 반 셀 좌표 편향과 보정 (`amcl_map_adapter`)

nav2_amcl (humble 1.1.x, `map/map.hpp`) 의 좌표 변환:

```
convertMap:  o' = o + (N/2)·s                       (o = OccupancyGrid origin, N = 폭 [셀], s = 해상도)
MAP_GXWX(x) = floor((x − o')/s + ½) + N/2 = floor((x − o)/s + ½)      ← 반올림
MAP_WXGX(i) = o' + (i − N/2)·s               = o + i·s                ← 셀 모서리
```

OccupancyGrid 규약에서 셀 i 는 [o + i·s, o + (i+1)·s) 인데 AMCL 은 [o + (i−½)s, o + (i+½)s) 로 본다. 즉 AMCL 내부
지도(우도장 포함)는 모든 구조물이 (−s/2, −s/2) 옮겨진 것과 같고, 스캔을 그 지도에 맞춘 추정 자세도 같은 만큼
치우친다 — s = 0.05 m 에서 축마다 2.5 cm, 대각 3.5 cm 로 **정지 3 cm 목표와 같은 크기**다.

보정: `amcl_map_adapter` (Python, 로봇 네임스페이스) 가 `/map` 을 받아 원점만 (+s/2, +s/2) 옮긴 사본을
`map_amcl` (transient_local) 로 재발행하고 AMCL 은 그것을 구독한다 (`amcl_half_cell_fix:=true` 기본). 그러면
`floor((x − o − s/2)/s + ½) = floor((x − o)/s)` 이고 `MAP_WXGX(i)` 는 셀 중심을 주어 두 변환이 모두 규약과 일치한다.
다른 `/map` 구독자(costmap, 추적기, kidnap_monitor, scan_matcher, 교통 관리)는 원본을 그대로 쓴다.
검증: `test_adapter_matches_installed_nav2_amcl_macros` 는 식을 다시 쓰지 않고 **설치된 nav2_amcl 헤더의 매크로 문자열을
읽어** 평가한다 — 보정 없이는 무작위 점의 ~50 % 가 옆 셀로 반올림되고, 보정 후 셀 = `floor((x − o)/s)`, 셀 → 월드 = 셀 중심
(nav2_amcl 이 매크로를 바꾸면 실패). convertMap 의 원점 이동은 헤더에 없어 소스 규약으로 둔다.

### 4.2 튜닝 과정

이전 기반(LiDAR 0.38 m 시절 지도)에서 `ros2 param set` 으로 σ_hit 0.05 / `update_min_d·a` 0.05 를 같은 경로로 비교했을 때
기준값(σ_hit 0.08, 0.10/0.08)보다 나아지지 않았고(날카로운 우도 → 파티클 고갈), 남은 오차가 일관되게 (−x, −y) 로 쏠려
§4.1 의 체계 편향을 찾았다. 그 스윕 수치는 이 기반에서 다시 재지 않았으므로 여기 싣지 않는다. 이 기반에서는 AMCL 설정을
그대로 두고 §4.3 의 정합을 더해 비교했다 (§6.3).

### 4.3 스캔-지도 점-대-면 정합 (`scan_registration`, `scan_matcher_node` → map EKF pose1)

AMCL 파티클 평균은 σ_hit 0.08 m 의 넓은 우도·유한 파티클 수 때문에 지도 대비 cm 단위로 흔들리고, 정지하면 마지막 갱신
오차가 굳는다 (§6.3 AMCL 만의 정지 오차). 스캔 수백 빔을 지도 면에 최소제곱으로 맞추면 지도 대비 자세를 mm 수준으로 정할
수 있으므로, 그 결과를 헤시안에서 얻은 공분산과 함께 map EKF 의 두 번째 절대 자세 입력으로 넣는다 (AMCL 은 전역 일관성·
납치 감지를 그대로 맡는다).

**지도 면 (맵당 1 회).** SLAM 띠의 한 층만 쓰면(가장 가까운 점유 셀 = AMCL 우도장 방식) 띠 폭 ±5 cm 안에서 비용이 평평해
정합이 떠다닌다. 그래서 자유 셀과 닿은 점유 셀마다 반지름 0.12 m 안 점유 셀 중심의 평균(= 띠 중심선)을 면 점 q_j, 반지름
0.20 m 이웃의 PCA 최소 고유벡터(자유 공간 쪽)를 법선 n_j 로 두고, λ_max/λ_min < 3 인 점(모서리·기둥 끝)은 점-대-점으로
다룬다. 현재 지도에서 8 193 점, 0.65 s (Gazebo 세션 로그).

**정합 (스캔마다, 초기값 = map EKF 의 map→base TF).** 자세 x = (t_x, t_y, θ), base 끝점 b_i (360 빔), p_i = R(θ) b_i + t,
대응 j(i) = p_i 에서 가장 가까운 면 점 (≤ 0.25 m — 지도에 없는 사람·지게차 빔은 버림):

```
r_i = n_jᵀ (p_i − q_j)                 J_i = [n_x, n_y, n_jᵀ R'(θ) b_i]        (R' = dR/dθ)
w_i = Huber(r_i; 2σ_r = 6 cm)           (JᵀWJ + μI) δ = −JᵀW r,  μ = 1e-4·tr/3   → x ← x + δ, 대응 재탐색, ≤ 15 회
수렴: 잘 구속된 고유 방향(λ > 1e-3 λ_max)에서 √(Σ λ_i δ_i² / Σw) < 0.1 mm
Σ_x = κ · s² (JᵀWJ)⁻¹,  s² = Σ w r² / (Σ w − 3),  κ = 10,  하한 σ_xy 5 mm, σ_θ 0.002 rad
```

- 통로처럼 한 방향 구속이 약하면 헤시안의 그 고유값이 작아 Σ 가 그 방향으로만 커지고 (합성 120 m 통로: Σ_xx > 100 Σ_yy),
  EKF 는 그 성분을 사실상 무시한다. 약한 방향은 수렴 판정에서 빼고 LM 감쇠 μ 로 걸음을 누른다.
- κ: 빔 잔차는 지도 격자·띠 모양을 공유해 독립이 아니므로 헤시안 역(독립 가정)은 과신이다. 합성 독립 잡음에서는 κ = 1 이
  실제 자세 분산과 맞고 (`test_hessian_covariance_matches_noise_monte_carlo`: 30 회 몬테카를로 대비 ×0.3~3), Gazebo 정지
  오차는 §6.3.
- 품질·게이트: 인라이어(대응 찾은 빔) ≥ 60 %, 수렴, 초기값에서 ≤ 0.3 m / 0.1 rad, 위치 상실(`localization/lost`) 중에는
  측정을 내지 않는다; EKF 쪽 `pose1_rejection_threshold` 5σ (Mahalanobis) 로 다른 국소 분지 정합을 버린다 (ekf.md §2).
- 스캔 시각의 EKF TF 가 아직 없으면(고부하에서 EKF TF 가 스캔보다 늦게 옴) 0.5 s 안의 최근 TF 로 초기화한다 — 초기값은
  분지(±0.25 m) 안이면 되고 결과 자세는 스캔 끝점이 정하므로 스캔 시각 자세다.

시험 (`test_scan_registration`, 합성 방 SLAM-같은 띠 지도 + 광선 투사 σ 0.03): 초기 오차 최대 15 cm / 3° 에서 참값 1.5 cm·0.3°
안으로 수렴, 빔 20 % 를 지도에 없는 가까운 끝점으로 바꿔도 2 cm 안, 납치 규모 초기 오차·빔 부족은 거부, 통로 퇴화 공분산,
면 점 법선이 자유 공간 쪽. `test_scan_matcher_node`: 지도·TF·스캔 콜백 → `scan_match_pose` (스캔 시각 스탬프, 공분산 배치),
최대 처리율, 최근 TF 대체와 나이 제한, 위치 상실 중 정지, 다른 분지 거부.

## 5. 납치(Kidnapped Robot) 감지와 복구

### 5.1 감지 (`kidnap_detector.py`, `scan_map_match.py`)

| 신호 | 식 | 역할 |
| --- | --- | --- |
| 공분산 급증 | AMCL `var_x + var_y > 0.5 m²` 또는 `var_yaw > 0.5 rad²` | 발산 (지속 경보) |
| 점프 | 연속 AMCL 갱신 사이 `‖Δp_amcl − Δp_odom‖ > 1.0 m` 또는 헤딩 0.5 rad | 오수렴·재수렴 (순간 사건 → SUSPECT 계기) |
| **스캔-맵 불일치** | 인라이어 비율 `ρ = #{d(끝점) ≤ 0.2 m}/#판정 빔 < 0.5` 가 5 스캔 연속 | **주 신호** (지속 경보) |

판정 빔 = 인라이어 + **지도의 벽을 뚫고 간 빔**. 지도에 없는 물체에 막혀 일찍 끝난 빔(끝점이 점유에서 멀고,
센서–끝점 사이에 지도상 막는 것이 없다)은 분자·분모에서 모두 뺀다 — 그렇게 하지 않으면 통로를 가로막은
미지 장애물(6 × 0.5 m 벽) 앞에서 올바르게 위치 추정한 로봇의 ρ 가 0.5 아래로 떨어져 거짓 LOST → 엉뚱한 전역
재초기화가 났다 (통합 시나리오 11 실측). 판정 빔이 `min_match_beams`(30) 미만이면 판정을 보류한다.

스캔-맵 일치도는 맵의 유클리드 거리 변환(AMCL likelihood field 와 같은 구조)을 맵당 한 번 만들고, 스캔 시각의
map 자세 = 마지막 AMCL 자세 ∘ (그 뒤 odom 상대 이동) 로 끝점을 옮겨 조회한다 (O(빔 수)).
**정지 중 납치**는 odom 이 움직임을 못 보므로 AMCL 이 갱신조차 하지 않아 공분산·점프로는 잡히지 않는다 —
그래서 일치도가 주 신호다. 상태: TRACKING → (경보) SUSPECT → `suspect_time` 1 s 지속 → LOST.
문턱 0.5 의 여유는 지도가 월드와 맞아야 나온다: 옛 지도(벽 0.2 m 이동 전·LiDAR 0.38 m)에서는 도크·스폰 줄에서 올바른
자세의 ρ 가 0.43~0.49 로 떨어져 거짓 LOST 가 났다 (리뷰). 현재 지도에서의 ρ 분포는 §6.4.

### 5.2 복구 (`global_seed.py`, `kidnap_monitor_node.py`)

LOST 선언 시 `localization/lost = true` (latched, BT `IsLocalized` 가 구독) 후 시도 k = 1, 2, … :

1. **전역 가설 탐색 (시드)** — 첫 시도에 현재 스캔 1 개로 **알려진 자유 셀**(점유까지 ≥ 0.3 m; 미지 셀 제외, §1)을
   0.5 m × 5° 격자로 훑어 캡 평균 거리 `m(h) = mean(min(d, 1 m))` (90 빔, 절사 없음)로 점수화 → 헤딩마다 상위
   50 개 → NMS(1 m / 20°) → 각 후보 주변 ±0.5 m / ±5° 를 0.1 m × 1° 로 정밀화(180 빔, 하위 80 % 절사 평균 —
   동적 장애물 가림 빔 제거). **최종 순위는 절사하지 않은 인라이어 비율** `ρ(h)`(끝점이 점유 셀 0.2 m 이내인 빔
   비율)로 매긴다: 절사 평균은 가림에 강하지만 별칭(창고의 점대칭 배치)을 가르는 소수 빔까지 버린다.
   시도 k ≤ `seed_attempts`(3) 는 k 번째 가설을 AMCL `initialpose` (σ 0.25 m, 5.7°) 로 넣는다.
   (제자리 회전으로 헤딩이 바뀌었으면 odom 헤딩 변화만큼 가설 헤딩을 옮긴다.)

   **구현 (`global_seed.GridScorer`)**: 가설 위치를 셀 중심에 두면 격자 좌표 `g = (c + ½, r + ½)` 에서 빔 끝점 셀은
   `(c, r) + floor(½ + R(ψ − ψ₀) b / res)` 로, 오프셋이 위치와 무관한 정수다. 헤딩마다 오프셋을 한 번 계산하고
   `flat[base_i + off_j]` 한 번의 gather 로 전체 가설 × 빔 점수를 낸다(테두리를 최대 빔 길이만큼 두른 거리장
   사본을 써서 맵 밖 끝점도 분기 없이 `max_distance`). `test_grid_scorer_matches_float_scorer` 가 부동소수 좌표 조회
   구현과 대조한다.
2. 시드가 소진되면 AMCL `reinitialize_global_localization` (알려진 자유 공간 균일 분포).
3. 각 시도마다 **제자리 회전 2π** (Nav2 `spin` 액션; 단독 시험은 `fallback_cmd_vel_topic`) — 360° LiDAR 라도
   회전은 `update_min_a` 를 넘겨 AMCL 갱신·리샘플을 구동해 파티클을 수렴시키고, 수렴 여부를 여러 방향에서 확인한다.
4. **수렴 판정 (별칭 거부 게이트)**: AMCL `var_x + var_y < 0.1 m²` 이고 `ρ ≥ 0.7` 이며, **별칭 여백**
   `ρ̃(현재 추정) − max ρ̃(다른 가설) ≥ converge_margin 0.05` 가 5 회 연속 → `ekf_filter_node_map/set_pose` 로 map EKF 를
   AMCL 평균으로 즉시 옮기고 `localization/lost = false`, 3 s 재감지 유예. 다른 가설 = 탐색이 낸 상위 가설 중 현재 추정에서
   1 m / 20° 밖인 것, 탐색 이후 odom 상대 이동만큼 옮긴 자세. ρ̃ = 그 자세 ±0.1 m / ±2° 격자(0.025 m / 0.5°)의 최대 인라이어
   비율 — 가설 격자(0.1 m × 1°)와 연속값인 AMCL 자세를 같은 조건으로 비교하려는 국소 정밀화다 (정밀화 없이 비교하면 대칭
   통로 시험에서 같은 별칭이 0.99 vs 0.94 로 갈려 틀린 쪽이 여백을 통과할 수 있었다).
   이전 판정(ρ ≥ 0.7 만)은 점대칭·주기 배치의 별칭이 ρ 0.70~0.93 을 내므로 틀린 가설을 받아들이고 다시 잡지 못했다 (리뷰).
   여백을 못 넘으면 수렴을 선언하지 않고 lost 를 유지한다 — 틀린 자세로 주행하는 것보다 안전 측이다.
   시험: `test_alias_margin_blocks_convergence_until_resolved` (여백 0.02 에서 10 회 보류, 여백 ≥ 0.05 두 번 연속에서 복귀),
   `test_alias_gate_rejects_symmetric_aisle_alias` (180° 회전 대칭 통로 합성 지도: 전역 탐색 1·2 위가 서로의 별칭이고, 어느 쪽을
   현재 추정으로 두어도 여백 < 0.05; 비대칭 방에서는 여백 ≥ 0.05).
5. 회전이 끝나도 수렴하지 않으면 다음 시도, 모두 실패하거나 120 s 초과면 FAILED (lost 유지, 수렴하면 언제든 복귀).

AMCL 균일 재초기화만으로는 60 × 40 m 창고에서 σ_hit 분지에 파티클이 떨어질 확률이 낮다 (research brief
§2.4: N = 5000, σ_hit 0.05 → 기대 적중 0.003 개). 시드 단계가 이를 결정적 탐색으로 바꾼다.
한계: 완전한 대칭 별칭은 스캔만으로 가를 수 없고 제자리 회전도 가르지 못한다(360° LiDAR) — 게이트가 틀린 수렴은 막지만
복구하지는 못하므로 lost 가 유지된다. 이동으로 가르는 DISAMBIGUATE 단계(brief §4.C)는 확장점이다 (`KidnapDetector` 의 시도
루프에 행동 추가; 별칭 여백이 오를 때까지 짧게 주행).

  GT 대비 2 cm 가 남는다.

판정에는 영향이 작지만, 조용한 호스트에서 다시 재는 것이 남은 과제다).
