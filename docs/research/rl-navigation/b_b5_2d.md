## 0. 결론 — 불리한 것 먼저

1. **주 집합 방향은 판정할 수 없다.** 사전 등록 규칙상 두 쪽 구간이 모두 0 을 빼야 "같은/반대 방향" 인데, Gazebo 주 결론
   (−1.0 %p [−3.0, +1.0]) 이 0 을 포함한다. 2D 주 집합 점추정의 부호는 Gazebo 와 **반대**다 (2D +0.92 %p, Gazebo −1.0 %p) — 기술로만 적는다.
2. **2D 주 집합의 RL 우세는 경로 출처에 민감하다.** 사전 등록 주 결론 P1 (main_3_15, 팀 A* 경로) 은 Δ = RL − DWA
   **+0.92 %p [+0.41, +1.48]** → "RL 이 높다" 이지만, 같은 시작·목표에 Isaac 풀 경로를 준 보조 실행(W1i)에서는
   **+0.29 %p [−0.18, +0.75] → 가르지 못함** 이다. 차이는 DWA 쪽이다 — 팀 A* 경로에서 DWA 실패 29 대 Isaac 경로 14 (출발 교착 8 대 5,
   목표 앞 정체 12 대 3, 중간 정체 9 대 6). RL 10 시드 평균은 0.9950 대 0.9960 으로 거의 같다. [측정·계산, §3·§6]
3. **2D-DWA 는 경로 위에서 멈추는 교착을 보인다** (주 집합 2 048 중 출발 교착 8 + 중간 정체 9, 팀 A* 경로). 정지 상태의 동적 창(v ≤ 0.05)
   에서는 속도 항 이득(0.4 × 0.05 = 0.02)보다 경로·헤딩 항 차이가 커서 v = 0 이 비용 최소가 되는 자리가 있다 (§4.3). 배포 BT 는 정적 세계에서
   경로를 다시 계획하지 않으므로 고정 경로는 배포와 같은 조건이지만, 2D 에는 Gazebo 의 EKF 속도·자세 잡음이 없다 — 이 교착이 Gazebo 에서 덜
   나는지는 **미측정** [추정: 잡음이 동률을 깰 수 있다]. Gazebo DWA 주 집합의 정체는 200 중 1 건이었다 (c_gazebo.md §3.3).
4. **스트레스 방향은 같지만 크기는 3.6 배다.** stress_3_30 (Gazebo 와 같은 길이 범위, 사전 등록 S1) Δ **+45.0 %p [+29.7, +59.0]** vs Gazebo
   +12.6 %p [+6.0, +19.6] → 규칙상 **같은 방향**. 그러나 크기 차에는 2D 쪽 조건이 크게 섞여 있다 (보충, §5 — 결과를 본 뒤의 분해다):
   - **집합 구성**: Isaac 스트레스 집합에는 목표 직진 여유 c < 0.20 m 인 목표가 48–55 % 있고 Gazebo 시나리오 v1 스트레스에는 23.5 % (c < 0.10
     은 0) 다. DWA 는 c < 0.20 에서 2D·Gazebo 모두 거의 못 간다 (2D 0.017–0.029, Gazebo 0.149).
   - **safety_lite**: 2D DWA 는 c ∈ [0.20, 0.30) 에서 0.47–0.53 으로 Gazebo DWA 0.87 보다 낮다. 2D DWA 의 목표 앞 정체 거리는 0.30 − c 보다
     중앙 0.035–0.041 m 멀다 — safety_lite 의 D 가 잡음 낀 빔들의 최솟값(정본은 창 통계 robustBeams)이라 STOP 이 일찍 걸린다고 본다 [추정].
   - Gazebo 의 구간 구성으로 2D 결과를 다시 가중하면 Δ ≈ +34–36 %p — 여전히 Gazebo 의 약 3 배다 [계산, 보충].
5. **2D 는 Isaac 보다 RL 에 불리하다**: 같은 정책·같은 행에서 2D − Isaac 은 주 −0.17 %p [−0.26, −0.07] (main_3_15), 스트레스 −6.6 %p
   [−8.2, −5.1] (stress_3_15; 10 시드 모두 2D 가 낮다). 시작 yaw 난수는 시뮬레이터마다 달라 행 단위 짝은 근사다. φ(safety_lite 대 정본)·
   기하(격자 대 정확)·충돌·레이캐스트가 함께 다르므로 어느 것이 원인인지 가르지 않았다 [측정·계산].
6. **같은 이름의 지표가 시뮬레이터마다 다르게 정의된다** (§7) — 2D 에는 위치추정·스캔 나이·깊이 카메라가 없고 플랜트는 명목(이상) 1 차 지연이며
   φ 는 safety_lite 다. 2D 의 숫자를 Gazebo 의 숫자와 같은 표에 놓을 때 크기 비교는 하지 않는다.
7. **실행·기록 결함 (모두 결과 전, 결과에 영향 없음)**: 첫 본 실행이 실행기의 npz 반복 해제로 12 분 동안 행 준비를 못 해 멈췄다 (결과 없음 —
   고친 커밋 `ba50060`, 실행 목록 `B5_attempt1_aborted`). 보조 실행 `B5_rl_s8_W1i`·`B5_rl_s9_W1i` 의 `dirty = true` 는 실행이 쓰지 않는 미추적
   파일(`tools/b5_supp.py`, 이 문서의 보충 집계 도구) 때문이다. 지도 점검 하나(Isaac 0.05 m 격자 후보)는 같은 디렉터리에 다음 실행이 덮어써
   원자료가 없다 (수치는 노트에만).

**측정으로 말할 수 있는 것** (위 한계 안에서):

- **스트레스 방향은 2D 10 시드·2D 시드 7·Gazebo 모두 같은 부호로 크다**: 2D 10 시드 Δ (stress_3_30 +45.0 %p, stress_3_15 +46.0 %p) 와 시드 7 (+43.8 · +45.3 %p)
  모두 구간이 0 을 빼고, 10 시드 모두 DWA 보다 높다 (부호 검정 p 0.002). Gazebo 와 "같은 방향" (사전 등록 규칙) 이다. RL 의 우세는 목표가
  좁을수록 커진다 — c < 0.20 m 에서 2D RL 0.55–0.76 대 DWA 0.02–0.03, Gazebo 에서 0.70 대 0.15 (보충).
- **2D 주 집합 (팀 A* 경로) 에서 RL 이 DWA 보다 높다** (P1, 확증): +0.92 %p [+0.41, +1.48], 10 시드 모두 양수 (부호 검정 p 0.002), 시드 7
  +1.12 %p (McNemar 정확 양측 p 6.6e-5). 단 경로 출처를 바꾸면 가르지 못한다 (0-2).
- **충돌**: 2D-DWA 0 / 5 120. RL 10 시드 합 4 / 51 200 (모두 main_3_15, 주행 중 접촉; 시드 7 은 1 건 — Isaac 에서도 시드 7 의 main_3_15 충돌은 1 건).
- 팀 DWA 코어를 2D 에 붙였다: 바인딩 한 걸음 출력 = 코어 직접 호출 (골든 5 사례 비트 일치), 배포 설정 94 키를 `nav2_params.yaml` 행 번호와 함께
  읽는다 (래퍼 configure() 의 param() 94 개와 정규식 대조), 시험 18 + 집계 시험 3, 변이 13 중 10 잡힘 (나머지 3 은 등가 — §8).
