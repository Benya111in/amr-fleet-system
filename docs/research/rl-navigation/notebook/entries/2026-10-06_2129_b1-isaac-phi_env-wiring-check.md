(3) 새 시험·도구가 위 변이들을 잡는가?

## 가설과 예측 (결과 보기 전)

- **H1 (결선이 맞다)**: 고치지 않은 코드에서 재생 불일치 0 (이산 정확, 연속 |Δ| ≤ 1e-9·max(1, |x|)), 불변식 위반 0.
  적용 범위 최소 (못 채우면 스텝을 늘린다 — 실패가 아니다): 재생 틱 ≥ 100 000, STOP 래치 틱 ≥ 1 000, 래치 켠 채 끝난 에피소드
  ≥ 20, 탈출 틱 ≥ 50, 에피소드 경계(리셋) ≥ 200.
  **버리는 조건**: 설명되지 않는 불일치·위반이 하나라도 있으면 결선 결함 — B 단계 전에 고친다.
- **H2 (변이를 잡는다)**: 각 변이를 git archive 사본에 넣고 같은 검사를 돌리면 모두 실패한다. 예측한 검출기:
  E1 → 관측 래치 비트 불변식, E2 (측정 대신 명령, 리뷰가 잡힌다고 한 것) → 재생 불일치, E3 → 스캔 시각 불변식 + 재생 불일치,
  E4 → 리셋 신선도 불변식 + 재생 불일치. E5·G3·G4 는 새 CPU 단위 시험(아래)이 잡는다 (g++ 없이).
  **버리는 조건**: 하나라도 살아남으면 그 변이에 대한 검출기를 고친다 — 동치 변이라는 주장은 근거를 적을 때만.
- **측정만 (방향 예측 없음)**: Isaac 실제 주행에서 원본 창 통계 가지치기(A3a)가 LiDAR 채널 거리 D 를 바꾸는 틱 비율과 크기,
  그리고 최종 명령을 바꾸는 틱 비율 — 가지치기 없는 그림자 게이트(torch CPU, 같은 입력)로 잰다. 리뷰 합성 배열의 25 % ·
  중앙 3.5 mm 와 비교한다.

## 설정

- **새 CPU 단위 시험** (`rl/isaac/tests/test_safety_gate_torch.py`, Isaac·g++ 불필요):
  G3 해제 거리 손 사례 (래치 뒤 D 0.40 에서는 유지, 0.55 에서 해제), G4 지연 보정 손 사례 (측정 0.4 m/s, 스캔 나이 0.2 s →
  D 가 0.08 m 짧아짐), CanonicalPhi 대 "명세대로 직접 부른 게이트" 순차 비교 (움직이는 측정·0.1 s 마다 새 스캔), CanonicalPhi.reset
  뒤 상태 = 새 게이트, `eval_metrics.nav2_update` (충돌 스텝 제외·첫 에피소드 뒤 무시 — eval_unbiased 가 이 함수를 쓰게 바꾼다).
  그리고 `AMR_ISAAC_REQUIRE_CPP=1` 이면 g++·Eigen 이 없을 때 C++ 교차 시험이 skip 이 아니라 실패한다.
- **env 안 교차 시험** `rl/isaac/scripts/record_phi_wiring.py` (Isaac) + `rl/isaac/tools/phi_crosscheck/replay_env.py` (amr-ai/rl:0.3, C++ 원본):
  - Isaac Lab 2.3.2, `AmrNavEnvCfg` (학습 풀 seed 0, **DR 켬** — 지연 1–4 서브스텝·LiDAR σ·빔 드롭아웃), `--phi canonical`,
    `lidar_source sensor`, N = 64 env, 결정 스텝 600 (60 s), env seed 777. 행동: env 0–31 은 A3c 정책(`policy_final.pt`)의 확률 행동
    (μ + σ·ε), env 32–63 은 원출력 U[−2, 2] 무작위 (충돌·래치·탈출을 늘리려고).
  - 기록 (게이트 호출을 감싸되 **값은 env 상태에서 따로 읽는다**): 결정 스텝마다 env.scan (거리 720), 서브스텝마다 플랜트 속도
    (φ 호출 시점), 프로파일러 출력 (`_pairs` 의 v_ref·w_ref), torch 게이트 출력 전부, 리셋된 env 와 그 결정 번호, 스텝 뒤 관측의
    래치 비트, set_scan 직후 게이트의 scan_stamp, 리셋 직후 게이트 상태.
  - 기대값 (명세에서 독립 계산): 결정 k 의 스캔 시각 = 0.1·k, 그 안 서브스텝 j 의 now = 0.1·k + 0.02·j, 빔 = (LIDAR_X, LIDAR_Y) +
    r(cos, sin) (무효 = NaN, `contract.scan_valid`), 점군 = 스캔마다 같은 시각의 빈 점군, 리셋 = 새 게이트.
  - 재생: 에피소드 구간마다 새 C++ SafetyGate (gate_runner seq) 에 위 기대 입력을 넣고 20 채널을 torch 기록과 비교 (A3a 와 같은 판정).
  - 불변식: |기록 scan_stamp − 0.1·k| ≤ 1e-9, 관측 래치 비트 = 그 결정 마지막 서브스텝의 prox (리셋된 env 는 0), 리셋 직후 게이트 상태
    = 새 게이트 상태 (모든 상태 텐서).
