## 해석

- **H1 (결선이 맞다) — 지지된다.** DR 켠 학습 설정의 Isaac 폐루프 960 000 틱·875 에피소드에서 env 상태로 독립 재구성한 입력의 C++ 재생이
  torch 출력과 이산 정확·연속 3.9e-11 이내로 같고, 결선 불변식 위반이 없다. B 단계 10 시드가 쓰는 결선은 safety_node 의미(스캔 시각 =
  결정 시작, 측정 = 플랜트 속도, 명령 = 프로파일러 출력, 리셋 = 새 게이트, 래치 → 관측)대로다.
- **H2 (변이를 잡는다) — 지지된다.** 8 개 모두 예측한 검출기에 걸린다. B 단계 결선 회귀는 CPU 시험(매 커밋)과 Isaac 검사(스냅숏마다
  약 2 분)로 잡을 수 있다.
- 말하지 않는 것: (1) 입력 **모델**이 Gazebo safety_node 의 실제 입력과 같다는 것 — 점군 'empty' 는 낙관 쪽이고, Gazebo 의 스캔 시각·
  전송 지연·바퀴 오도메트리 측정은 Isaac 의 "결정 시작·플랜트 속도" 와 다를 수 있다 (D4 전이 점검 몫). (2) Isaac 에서 안 나오는 가지
  (트랙·도킹 예외·점군 점) — A3a 합성 교차 시험만 덮는다.
- **가지치기**: 배포 safety_node 가 헤더 정의보다 덜 보수적인 D 를 쓰는 일이 실제 주행 틱의 약 20 % 에서 나고, 드물게 정지 판정까지
  바꾼다 (stress 318 틱). 이식은 원본 그대로라 학습·배포 φ 는 일치한다 — 결함 여부·수정은 amr_perception 소유자 판단이다 (요청에 이
