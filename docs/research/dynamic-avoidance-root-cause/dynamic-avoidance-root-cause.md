## 3. 근본 원인 — v→0 인 순간 세 겹이 동시에 무너진다

일곱 분야(제어이론·계산기하·VO·군중내비·시공간계획·최적화·예측)가 독립적으로 리서치했고
서로 다른 언어로 같은 대상을 가리켰다. **계획기가 표현할 수 있는 미래의 집합이, 회피가 필요한
바로 그 순간에 하나(제자리에 머무름)로 붕괴하고, 그 위의 안전 판정이 그 유일한 미래를
"안전" 으로 분류한다.**

### 3.1 시간 붕괴 — 자기 모형 오차 [코드로 검증]

`dynamicWindow`(`src/amr_navigation/src/core/dwa.cpp:107`)는 **1주기** 도달집합 `v_c ± a·Δt_c` 인데,
`rollout`(`dwa.cpp:165`)은 `integrateArc(start, v, w, k·dt)` 로 그 속도를 `T_sim` **내내 등속 유지**한다.

- v=0 에서 창은 `[0, 0.05] × [±0.1]` → 후보 342개 전체의 1.5 s 종점 변위가 **0.075 m** 안
- 실제 도달거리는 저크 2.0 을 반영해도 **0.75 m**, 가속만 보면 1.125 m → **10~15배** 차이
- 모든 비용항의 해상도 이하 → argmin 이 평탄 → 선택이 전부 tie-break 로 떨어진다

계획기는 자기를 "1.5 초에 7.5 cm 가는 물체" 로 본다. "돌고 나서 가속해 빠져나간다" 는 기동이
**후보로 존재하지 않는다.**

### 3.2 각 붕괴 — 유일한 제어 채널의 소거 [코드로 검증]

`chordVelocity`(`src/amr_navigation/src/core/velocity_obstacle.cpp:18`)는 v=0 에서
`mag = v·sin(half)/half = 0` 이므로 **ω 와 무관하게 정확히 (0,0)** 을 돌려준다.

차동구동 로봇이 v→0 에서 온전히 보유한 **유일한** 제어 입력이 회전(ω)인데, 그 회전이 동적
술어에서 **구조적으로 소거**된다.

외접원 `robot_radius = 0.361` 은 **두 번째·약한** 사례다 — `dwa.cpp:408/428`(in_body), `:552`(VO 반경),
`:667`(TTC 반경), `:686/706`(통로 반폭)이 전부 이 스칼라를 쓰고 외접원은 SO(2) 불변이다.
다만 `chordVelocity` 가 먼저 0 으로 만들기 때문에 기하가 개입할 자리조차 없다.

> `core/footprint_reach.hpp` 는 이 문제를 풀려고 작성되어 `test_footprint_reach.cpp` 로 시험까지
> 통과하는데 **프로덕션 호출이 0건**이다(grep 확인). 구현이 아니라 **배선**이 없다.

### 3.3 판정 붕괴 — 여유를 늘리면 눈먼 구간이 늘어난다 [실측]

접촉 시점 `‖p‖` 는 중앙 **0.594 m**, 최대 0.659 m 인데 `R_vo = 0.361 + 0.25 + 0.30 = 0.911 m` 다.
즉 접촉의 거의 전부가 `R_vo` **안**에서 일어나고, `velocityObstacleTime` 의 `pn2 < R*R` 조기 반환이 걸린다.

**결과: R 을 키우면 전면 포화가 더 일찍 시작된다. 모든 "여유를 늘리자" 실험은 기제적으로
"눈먼 구간을 늘리자" 실험이었다.** 이득이 없거나 악화된 것이 당연하다.

같은 이유로 `vo_time_horizon` 2.0 → 3.0 은 **반드시 악화**시킨다 (VO^τ 는 τ 에 단조 증가).

### 3.4 그 위에 — 안전 판정 집합 자체가 틀렸다

시스템이 구현한 것은 **passive motion safety**("충돌이 일어난다면 로봇은 정지 상태였다",
Fraichard 계열 braking-ICS)이고, 명세가 요구하는 것은 **active safety**(접촉 0)다.

Braking-ICS 가 유효하려면 종단 집합 `{v=0}` 이 제어불변이어야 하는데, 1.0 m/s 로 양보 없이
걸어오는 보행자 앞에서 정지 상태는 후속 안전 상태를 갖지 않는다. **암묵 terminal set 이 무효이고
recursive feasibility 가 존재하지 않는다.** 접촉의 52 %가 정지 상태인 것이 그 직접 증거다.

**정지를 위험으로 표현할 수단이 코드에 없다** [검증]:
- `ttc.cpp:79` `path_speed = max(|speed|, 0.2)` → 80행 `fromPath` 가 먼저 성공하므로,
  **멈춘 로봇도 경로를 0.2 m/s 로 빠져나가는 것으로 예측**된다. 정지 위험을 구조적으로 은폐한다.
  (83행 `stationary` 는 `fromPath` 가 실패해야만 닿는다.)
- `dwa.cpp:673` `excess = max(0, |v| − v_safe)/v_span` → **v=0 에서 항상 0**. 정지 후보를 벌할 수단이
  아예 없다. 남는 `urgency` 는 후보의 v·ω 가 아니라 ttc 만의 함수이고, 그 ttc 는 667행에서
  외접원으로 계산되어 **요(yaw)에 불변**이다. 게다가 675행 `min(1.0, ...)` 클리핑이라 정확 벌점도 아니다.

### 3.5 시간축 주변화 [실측]

A(−4,−5)→B(4,−9) 경로 × `worker_crossing` 반주기(15.24 s)의 (s,t) 직사각형 136.3 m·s 중
실제 충돌집합은 **넓이 3.07 m·s 의 타원 하나, 2.25 %** 뿐이다. 이것을 s 축으로 사영하면 2.96 m
(경로의 33 %)의 벽이 되고, 모든 차선을 합쳐 사영하면 실측 94 %가 된다 — **42배의 정보 손실**.

회피는 자유측도 5.7 %인 좌표(공간)에서 시도되고, 자유측도 97.8 %인 좌표(시간)는 상태공간에
아예 없다. 90° 횡단의 실제 공간-시간 충돌 상자는 **1.10 m × 0.90 s** 에 불과하다 —
**0.9 초짜리 틈이 있는데 시간축이 없어서 보이지 않았다.**

## 4. 내가 틀렸던 것 (지우지 말 것)

### 4.1 "침투 6 mm = 경계 포화" — **거짓**

내가 세션 내내 주장했던 해석이다. 근거로 쓴 것은 침투 중앙 6.0 mm / 최대 18.8 mm 였고,
"여유를 더 줘도 평형이 새 경계로 옮겨갈 뿐" 이라고 설명했다.

**실측 재검증** (`checks/c1_census.py` §4.1, 147건 전수):
- `collision_monitor_node.py:127` 은 `d < 0` 이 되는 **첫 표본**을 기록하고 래치한다.
- ground truth 는 **50 Hz** (`dynamic_obstacles.yaml:21`) → 20 ms 간격.
- 따라서 기록 가능한 침투의 상한은 `|v_rel| × 0.020` 이다.
- **상한을 넘는 표본 0 / 147.** 침투는 여유의 척도가 아니라 **검열된(censored) 관측량**이다.

단, 순수 표집 위상 산물도 아니다 — 침투/상한 비율의 KS 통계량이 균등분포 대비 **D = 0.319**
(임계 0.112)로 균등을 강하게 기각한다(중앙 0.277, 평균 0.331). 스치듯 경계를 넘는 접촉이 많다는 뜻이다.

> 이 수치를 처음 손으로 계산했을 때 `nan` 이 섞여 중앙값이 0.175 로 나왔다. `checks/c1_census.py`
> 가 비유한 값을 거르고 나서야 맞았다. **손으로 낸 수치는 브리프에 쓰지 않는다.**

**결론**: 6 mm 로 기록된 접촉이 "6 mm 만 더 있었으면 됐다" 를 뜻하지 않는다. 첫 교차에서
측정을 멈추는 것뿐이고 실제 침투는 계속 자란다. **`footprint_reach.hpp:19-25` 주석의 "84.8 %"
논거는 검열된 양과 비교한 것이라 무효다 — 고쳐야 한다.**

여유 증가가 실패한 **진짜** 이유는 §3.3 이다.

### 4.2 "N8 이 Q8 보다 나쁘다" — 근거 없음

`merge_min_gap` 수정 후 접촉 5/90 vs 수정 전 3/120 을 보고 악화로 읽을 뻔했다.
Fisher 양측 **p = 0.2923**, 95 % CI 가 2.40~7.09 % 에서 크게 겹친다. **구분 불가다.**
클러스터링 수정의 근거는 단위 수준(격자 41→0칸)이지 08 결과가 아니다.

### 4.3 합성 기하로 파라미터를 고른 것 (merge_min_gap 0.30)

다리 모형을 반지름 0.06 / 간격 0.30(표면 0.18)으로 잡았는데 실제 액터는 반지름 0.048 /
표면 간격 **0.235** 였다. 실제 단면으로 재서 **0.38** 로 정정했다(커밋 f7b0adf).
**교훈: 파라미터를 고르기 전에 실제 기하를 유도하라.**

### 4.4 첫 재현 실험 설계 오류

선반을 목표 거리에 **상대** 배치해서 `max_range: 12.0` 밖으로 나가버렸고, 그 결과
"근거리에서만 분할된다" 는 틀린 결론을 냈다. 고정 배치로 다시 재니 전 구간 분할이었다.

### 4.5 알림을 따라가 우선순위를 놓친 것

워크플로 완료 알림이 오면 그 실을 따라가버렸고, 내가 만든 P0 우선순위를 내가 안 지켰다.
**새 알림이 와도 먼저 이 문서 §6 을 확인한다.**

## 6. 실행 계획 — 결정 관문 포함

**불변식** (모든 단계에 적용):
- **A**: 안전 게이트 거부권은 한 방향. 상위가 E-stop·sensor_stop·command_stale·zone limit 을
  완화할 수 있게 만드는 변경은 즉시 탈락.
- **B**: 기존 계약을 깨지 말고 설계를 고친다. 깨야 한다면 그 계약이 인코딩한 트레이드오프를 먼저 밝힌다.
- **C**: 한 번에 하나씩 바꾸고 각각 측정한다.
- **D**: 모든 측정은 `nav2_params.snapshot.yaml` + `perception.snapshot.yaml` + `HEAD.txt` +
  `uncommitted.txt` 를 남긴다.

### R0 — 계측 기반 교체 (런타임 무변경) ← **지금 여기**

접촉률은 1차 지표가 될 수 없고(§2), 침투는 지표조차 아니다(§4.1). **주기별 기제 지표**로 바꾼다.
시행당 수천 표본이므로 검정력 문제에서 벗어난다.

기록할 것 (DWA 주기마다):
1. `best == nullptr` 여부와 후보 비용 `max − min` → §3.1 의 "평탄한 argmin" 을 폐루프에서 확인
2. `n_valid`, `n_vo_rejected`, `n_samples` → **포화율** = (n_vo_rejected == n_valid)
3. `min_k firstContactTime` 과 최근접 동적 트랙까지 `‖p‖` → §3.3 의 조기반환 지배 여부
4. 후보 `|v_eff|` 스팬 → §3.1 의 표현력 결손을 직접 관측
5. 주기별 `cmd_v` / `gate_out_v` → 계획기가 닿는 인구와 게이트가 지운 인구를 가른다
6. `escaping` / `leave_lane` / `drop_spin` 플래그

**반드시 함께**: `tests/integration/test_08_dynamic_obstacles.py` 의 열 목록을 같이 고친다 —
안 고치면 배열에 붙여도 디스크에 안 남는다.
**함께**: `footprint_reach.hpp:19-25` 주석 정정 (§4.1).

**결정 관문**: 지표 3이 "`firstContactTime` 이 이미 포화 → 반경 안에서 정보를 주지 않는다" 로
나오면 R1/R2 의 값어치가 0 이고 R3(참 호 접촉 판정)이 먼저다. **R0 이 끝나기 전에는
R1/R2 에 한 줄도 쓰지 않는다.**

### R1 + R2 — 후보 집합의 표현력 복원 (분리 불가)

- **R1**: `rollout` 을 등속 원호에서 **가속 실현가능(램프) 적분**으로. 호길이 색인 재유도 필수.
- **R2**: 표본을 1주기 도달속도가 아니라 **지속 목표명령** `[min_vel_x, v_cap] × [±max_vel_theta]`
  으로. 창은 "표본 필터" 가 아니라 "방출 명령 클램프" 로 재정의. 방출은 `control_period`(0.05 s)
  시점의 램프 상태 → 하류 계약 불변.
- **반드시 같은 커밋에서 `J_dyn`(dwa.cpp:673-675) 을 고친다.** 안 고치면 R2 가 만든 빠른 후보가
  정확히 최대 벌점을 받아 효과가 상쇄된다.

**정량 근거**: v_meas=0 에서 후보의 상대속도 **방향 스팬이 ±2.87°** 인데 VO 콘 반각은
d=1.6 m 에서 34.7° → 탈출에 **0.569 m/s(창의 11.4배)** 필요. 여유를 0 으로 해도 4.7~7.6배.
**결손은 술어의 모양이 아니라 achievable set 의 크기다.**

**성공 기준**: "접촉 감소" 가 아니라 **"명령된 |v_eff| 가 0.35~0.57 m/s 대역에 도달하는가"**.
도달 자체가 안 되면(게이트가 램프 중 깎으면) R1/R2 의 독립 효과는 0 이고 다음은 R5(게이트 수용성)다.

### R3 — 동적 하드 제약을 현(chord) 근사에서 참 호(arc) 접촉 판정으로

§3.2·§3.3 을 동시에 친다. v=0 에서 `chordVelocity ≡ (0,0)` 인 축퇴와 `pn2 < R*R` 조기 반환을 없앤다.

### R4 — `footprint_reach` 를 처음으로 배선 (방위 의존 기하)

죽은 코드를 살린다. 단 §4.1 로 **"84.8 %" 논거는 무효**이므로 기대 효과를 다시 유도해야 한다.

### R5 — 정지 백업을 검증된 회피 백업으로 (gatekeeper 식 커밋 궤적 필터)

§3.4 를 고치는 **유일한** 항목. 매 주기 "공칭 궤적 접두부 + 백업 기동 접미부" 를 짧은 유한
지평으로 전방 적분해 검증하고, 검증 통과 후보만 남긴다. 실패 시 직전 커밋 궤적을 계속 실행
→ recursive feasibility. **안전 게이트는 한 줄도 건드리지 않는다** (불변식 A).

### R6 — 창 중심 되먹임 정정 (독립, R1 과 병행 가능)

`dwa_controller.cpp:543` `v_last_ = res.v` 는 **게이트를 거치지 않은** 계획기 자신의 출력을 다음
주기 창 중심으로 되먹인다. 게이트가 0 으로 깎는 동안 모든 롤아웃이 반사실(counterfactual)이다.

### 별건 — 명세 "재계획하여 회피" (P0-1)

설계 워크플로 결과는 `scratchpad/design_replan.json`. 승자는 "TTC-gated re-admission" 이었으나
