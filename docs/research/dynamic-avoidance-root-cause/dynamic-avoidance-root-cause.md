## 3. 근본 원인 — v→0 인 순간 세 겹이 동시에 무너진다

일곱 분야(제어이론·계산기하·VO·군중내비·시공간계획·최적화·예측)가 독립적으로 리서치했고
서로 다른 언어로 같은 대상을 가리켰다. **계획기가 표현할 수 있는 미래의 집합이, 회피가 필요한
바로 그 순간에 하나(제자리에 머무름)로 붕괴하고, 그 위의 안전 판정이 그 유일한 미래를
"안전" 으로 분류한다.**

### 3.1 시간 붕괴 — 자기 모형 오차 [코드로 검증]

`dynamicWindow`(`src/amr_navigation/src/core/dwa.cpp:107`)는 **1주기** 도달집합 `v_c ± a·Δt_c` 인데,
`rollout`(`dwa.cpp:165`)은 `integrateArc(start, v, w, k·dt)` 로 그 속도를 `T_sim` **내내 등속 유지**한다.

- v=0 에서 창은 `[0, 0.05] × [±0.1]` → 후보 342개 전체의 1.5 s 종점 변위가 **0.075 m** 안
- 실제 도달거리는 저크 2.0 을 반영해도 **0.75 m**, 가속만 보면 1.125 m → **10~15배** 차이
- 모든 비용항의 해상도 이하 → argmin 이 평탄 → 선택이 전부 tie-break 로 떨어진다

계획기는 자기를 "1.5 초에 7.5 cm 가는 물체" 로 본다. "돌고 나서 가속해 빠져나간다" 는 기동이
**후보로 존재하지 않는다.**

### 3.2 각 붕괴 — 유일한 제어 채널의 소거 [코드로 검증]

`chordVelocity`(`src/amr_navigation/src/core/velocity_obstacle.cpp:18`)는 v=0 에서
`mag = v·sin(half)/half = 0` 이므로 **ω 와 무관하게 정확히 (0,0)** 을 돌려준다.

차동구동 로봇이 v→0 에서 온전히 보유한 **유일한** 제어 입력이 회전(ω)인데, 그 회전이 동적
술어에서 **구조적으로 소거**된다.

외접원 `robot_radius = 0.361` 은 **두 번째·약한** 사례다 — `dwa.cpp:408/428`(in_body), `:552`(VO 반경),
`:667`(TTC 반경), `:686/706`(통로 반폭)이 전부 이 스칼라를 쓰고 외접원은 SO(2) 불변이다.
다만 `chordVelocity` 가 먼저 0 으로 만들기 때문에 기하가 개입할 자리조차 없다.

> `core/footprint_reach.hpp` 는 이 문제를 풀려고 작성되어 `test_footprint_reach.cpp` 로 시험까지
> 통과하는데 **프로덕션 호출이 0건**이다(grep 확인). 구현이 아니라 **배선**이 없다.

### 3.3 판정 붕괴 — 여유를 늘리면 눈먼 구간이 늘어난다 [실측]

접촉 시점 `‖p‖` 는 중앙 **0.594 m**, 최대 0.659 m 인데 `R_vo = 0.361 + 0.25 + 0.30 = 0.911 m` 다.
즉 접촉의 거의 전부가 `R_vo` **안**에서 일어나고, `velocityObstacleTime` 의 `pn2 < R*R` 조기 반환이 걸린다.

**결과: R 을 키우면 전면 포화가 더 일찍 시작된다. 모든 "여유를 늘리자" 실험은 기제적으로
"눈먼 구간을 늘리자" 실험이었다.** 이득이 없거나 악화된 것이 당연하다.

같은 이유로 `vo_time_horizon` 2.0 → 3.0 은 **반드시 악화**시킨다 (VO^τ 는 τ 에 단조 증가).

### 3.3.1 두 축퇴는 합성된다 — 한쪽만 고쳐서는 안 되는 이유 [코드 인용]

`velocity_obstacle.cpp:46-53`
```cpp
double velocityObstacleTime(const Point2D & p, const Point2D & w_rel, double R, double tau)
{
  const double pn2 = p.x * p.x + p.y * p.y;
  const double closing = p.x * w_rel.x + p.y * w_rel.y;
  if (pn2 < R * R) {
    return closing > 0.0 ? 0.0 : kInf;   // ← 후보 속도와 무관
  }
```

`velocity_obstacle.cpp:80-83` (`firstContactTime`)
```cpp
  Point2D r0 = rel(0);
  if (r0.x * r0.x + r0.y * r0.y < R * R) {
    return 0.0;                          // ← 시작 자세만 보고 후보 무관
  }
```

즉 장애물이 `R` 안에 들어오는 순간 **두 술어가 모든 후보에게 같은 값**을 준다. 그런데
`R_vo = 0.911 m` 이고 접촉 시점 `‖p‖` 중앙이 0.594 m 다.

여기에 §3.1(창 붕괴)과 §3.2(`chordVelocity ≡ 0`)가 겹치면 **네 겹이 같은 방향으로 작동한다**:

| 겹 | 결과 |
| --- | --- |
| 창 붕괴 | 후보의 v 가 [0, 0.05] — 후보가 물리적으로 거의 같다 |
| 등속 롤아웃 | 그 차이가 1.5 s 뒤 0.075 m 로 남는다 |
| `chordVelocity ≡ 0` | ω 가 상대속도에 나타나지 않는다 |
| `‖p‖ < R` 조기 반환 | v 도 나타나지 않는다 (모두 0 또는 inf) |

**따라서 R1/R2(후보 집합을 넓힘)만 해도, R3(술어 축퇴 제거)만 해도 부족할 수 있다.**
넓힌 후보가 `R` 안에서 여전히 구별되지 않고, 구별되는 술어가 후보가 같으면 쓸 데가 없다.
R0 의 결정 관문은 **어느 쪽이 지배적인가**를 판정하는 것이지 한쪽만 하면 된다는 뜻이 아니다.

### 3.4 그 위에 — 안전 판정 집합 자체가 틀렸다

시스템이 구현한 것은 **passive motion safety**("충돌이 일어난다면 로봇은 정지 상태였다",
Fraichard 계열 braking-ICS)이고, 명세가 요구하는 것은 **active safety**(접촉 0)다.

Braking-ICS 가 유효하려면 종단 집합 `{v=0}` 이 제어불변이어야 하는데, 1.0 m/s 로 양보 없이
걸어오는 보행자 앞에서 정지 상태는 후속 안전 상태를 갖지 않는다. **암묵 terminal set 이 무효이고
recursive feasibility 가 존재하지 않는다.** 접촉의 52 %가 정지 상태인 것이 그 직접 증거다.

**정지를 위험으로 표현할 수단이 코드에 없다** [검증]:
- `ttc.cpp:79` `path_speed = max(|speed|, 0.2)` → 80행 `fromPath` 가 먼저 성공하므로,
  **멈춘 로봇도 경로를 0.2 m/s 로 빠져나가는 것으로 예측**된다. 정지 위험을 구조적으로 은폐한다.
  (83행 `stationary` 는 `fromPath` 가 실패해야만 닿는다.)
- `dwa.cpp:673` `excess = max(0, |v| − v_safe)/v_span` → **v=0 에서 항상 0**. 정지 후보를 벌할 수단이
  아예 없다. 남는 `urgency` 는 후보의 v·ω 가 아니라 ttc 만의 함수이고, 그 ttc 는 667행에서
  외접원으로 계산되어 **요(yaw)에 불변**이다. 게다가 675행 `min(1.0, ...)` 클리핑이라 정확 벌점도 아니다.

### 3.5 시간축 주변화 [실측]

A(−4,−5)→B(4,−9) 경로 × `worker_crossing` 반주기(15.24 s)의 (s,t) 직사각형 136.3 m·s 중
실제 충돌집합은 **넓이 3.07 m·s 의 타원 하나, 2.25 %** 뿐이다. 이것을 s 축으로 사영하면 2.96 m
(경로의 33 %)의 벽이 되고, 모든 차선을 합쳐 사영하면 실측 94 %가 된다 — **42배의 정보 손실**.

회피는 자유측도 5.7 %인 좌표(공간)에서 시도되고, 자유측도 97.8 %인 좌표(시간)는 상태공간에
아예 없다. 90° 횡단의 실제 공간-시간 충돌 상자는 **1.10 m × 0.90 s** 에 불과하다 —
**0.9 초짜리 틈이 있는데 시간축이 없어서 보이지 않았다.**

## 4. 내가 틀렸던 것 (지우지 말 것)

### 4.1 "침투 6 mm = 경계 포화" — **거짓**

내가 세션 내내 주장했던 해석이다. 근거로 쓴 것은 침투 중앙 6.0 mm / 최대 18.8 mm 였고,
"여유를 더 줘도 평형이 새 경계로 옮겨갈 뿐" 이라고 설명했다.

**실측 재검증** (`checks/c1_census.py` §4.1, 147건 전수):
- `collision_monitor_node.py:127` 은 `d < 0` 이 되는 **첫 표본**을 기록하고 래치한다.
- ground truth 는 **50 Hz** (`dynamic_obstacles.yaml:21`) → 20 ms 간격.
- 따라서 기록 가능한 침투의 상한은 `|v_rel| × 0.020` 이다.
- **상한을 넘는 표본 0 / 147.** 침투는 여유의 척도가 아니라 **검열된(censored) 관측량**이다.

단, 순수 표집 위상 산물도 아니다 — 침투/상한 비율의 KS 통계량이 균등분포 대비 **D = 0.319**
(임계 0.112)로 균등을 강하게 기각한다(중앙 0.277, 평균 0.331). 스치듯 경계를 넘는 접촉이 많다는 뜻이다.

> 이 수치를 처음 손으로 계산했을 때 `nan` 이 섞여 중앙값이 0.175 로 나왔다. `checks/c1_census.py`
> 가 비유한 값을 거르고 나서야 맞았다. **손으로 낸 수치는 브리프에 쓰지 않는다.**

**결론**: 6 mm 로 기록된 접촉이 "6 mm 만 더 있었으면 됐다" 를 뜻하지 않는다. 첫 교차에서
측정을 멈추는 것뿐이고 실제 침투는 계속 자란다. **`footprint_reach.hpp:19-25` 주석의 "84.8 %"
논거는 검열된 양과 비교한 것이라 무효다 — 고쳐야 한다.**

여유 증가가 실패한 **진짜** 이유는 §3.3 이다.

### 4.2 "N8 이 Q8 보다 나쁘다" — 근거 없음

클러스터링 수정의 근거는 단위 수준(격자 41→0칸)이지 08 결과가 아니다.

### 4.3 합성 기하로 파라미터를 고른 것 (merge_min_gap 0.30)

소요 3237~3350 s (기준선 532, 시행이 잘려 18/17/19 만 돌았다).

| `cost_span` 중앙 | 0.0712 | **0.8500** | 후보가 실제로 구별된다 |
| `\|cmd_v\|` 중앙 | 0.8800 | **0.1102** | 그런데 계획기가 **느린 후보만 고른다** |
| `\|cmd_w\|` 중앙 | 0.1347 | 0.3408 | 대신 더 돈다 |
| 시행당 주기 | 322 | **3261** | 10 배 오래 걸린다 |

원인은 내가 같은 커밋에서 건드린 `J_dyn`(dwa.cpp:673) 이다.
`excess = max(0, |v| − v_safe)/v_span` 은 `c.v` 가 1주기 창 [0, 0.05] 에 갇혀 있는 동안
**항상 0 인 죽은 항**이었다. 후보를 넓히면서 `|c.v|` 를 `c.v_peak`(롤아웃 중 최대 속도, 최대
0.85)로 바꾸자 장애물이 가까워 `v_safe` 가 작을 때 **빠른 후보에만 큰 벌점을 주는 살아 있는
항**이 됐다. 반증자가 정확히 이것을 경고했는데("R2 가 만든 빠른 후보가 675 행에서 정확히 최대
벌점을 받아 효과가 상쇄된다") **나는 방향을 반대로 고쳤다.**

> **정정 (2026-09-30)**: 원인이 하나가 아니었다. `J_dyn` 말고 **방출단의 저크 이중 적용**이
> 더 컸다. 파이프라인이 `dwa -> velocity_profiler(저크 성형) -> safety_node` 인데 계획기가
> 방출값에도 저크를 걸어, 정지에서 `a = j·dt = 0.1` 이므로 `v_emit = 0.005 m/s` — 종전 창
> 상한 0.05 의 **1/10** 이었다. 이것만 고치니 `|cmd_v|` 가 0.11 → 0.80 으로 회복됐고
> 소요도 기준선으로 돌아왔다. **롤아웃은 저크를 계속 모형화한다** (예측이 낙관적이면 안 되고,
> 실제 로봇은 프로파일러가 성형한 대로 움직이므로 롤아웃이 맞다). 방출만 다르다.
>
> 그리고 `cost_probe` 가 §4.6 의 진단을 수치로 확인했다 — 1주기 창에서 `dynamic` 항의
> 가중 기여 폭이 **정확히 0.0000** 이다. 후보가 구별되면 0.26~0.33 (37~41 %) 이 된다.

**이것이 이 조사에서 가장 중요한 발견이다**: 비용 가중치가 **망가진 후보 집합에 맞춰 튜닝돼
있었다.** 후보들이 서로 구별되지 않는 동안에는 어떤 가중치든 결과가 같았으므로, 지금의 8 항
가중합은 "타당해서" 가 아니라 **"아무것도 결정하지 않아서" 살아남은 값**이다.
§5 의 "116 구성 스윕 무반응" 과 같은 동전의 양면이고, 후보 집합을 고치는 순간 드러난다.

따라서 **R1/R2 와 비용 함수는 분리할 수 없다.** 순서는 비용 함수가 먼저다.

### 4.5 알림을 따라가 우선순위를 놓친 것

워크플로 완료 알림이 오면 그 실을 따라가버렸고, 내가 만든 P0 우선순위를 내가 안 지켰다.
**새 알림이 와도 먼저 이 문서 §6 을 확인한다.**

### R0 — 계측 기반 교체 (런타임 무변경) ← **지금 여기**

접촉률은 1차 지표가 될 수 없고(§2), 침투는 지표조차 아니다(§4.1). **주기별 기제 지표**로 바꾼다.
시행당 수천 표본이므로 검정력 문제에서 벗어난다.

기록할 것 (DWA 주기마다):
1. `best == nullptr` 여부와 후보 비용 `max − min` → §3.1 의 "평탄한 argmin" 을 폐루프에서 확인
2. `n_valid`, `n_vo_rejected`, `n_samples` → **포화율** = (n_vo_rejected == n_valid)
3. `min_k firstContactTime` 과 최근접 동적 트랙까지 `‖p‖` → §3.3 의 조기반환 지배 여부
4. 후보 `|v_eff|` 스팬 → §3.1 의 표현력 결손을 직접 관측
5. 주기별 `cmd_v` / `gate_out_v` → 계획기가 닿는 인구와 게이트가 지운 인구를 가른다
6. `escaping` / `leave_lane` / `drop_spin` 플래그

**반드시 함께**: `tests/integration/test_08_dynamic_obstacles.py` 의 열 목록을 같이 고친다 —
안 고치면 배열에 붙여도 디스크에 안 남는다.
**함께**: `footprint_reach.hpp:19-25` 주석 정정 (§4.1).

**결정 관문**: 지표 3이 "`firstContactTime` 이 이미 포화 → 반경 안에서 정보를 주지 않는다" 로
나오면 R1/R2 의 값어치가 0 이고 R3(참 호 접촉 판정)이 먼저다. **R0 이 끝나기 전에는
R1/R2 에 한 줄도 쓰지 않는다.**

### R1 + R2 — 후보 집합의 표현력 복원 (분리 불가)

- **R1**: `rollout` 을 등속 원호에서 **가속 실현가능(램프) 적분**으로. 호길이 색인 재유도 필수.
- **R2**: 표본을 1주기 도달속도가 아니라 **지속 목표명령** `[min_vel_x, v_cap] × [±max_vel_theta]`
  으로. 창은 "표본 필터" 가 아니라 "방출 명령 클램프" 로 재정의. 방출은 `control_period`(0.05 s)
  시점의 램프 상태 → 하류 계약 불변.
- **반드시 같은 커밋에서 `J_dyn`(dwa.cpp:673-675) 을 고친다.** 안 고치면 R2 가 만든 빠른 후보가
  정확히 최대 벌점을 받아 효과가 상쇄된다.

**정량 근거**: v_meas=0 에서 후보의 상대속도 **방향 스팬이 ±2.87°** 인데 VO 콘 반각은
d=1.6 m 에서 34.7° → 탈출에 **0.569 m/s(창의 11.4배)** 필요. 여유를 0 으로 해도 4.7~7.6배.
**결손은 술어의 모양이 아니라 achievable set 의 크기다.**

**성공 기준**: "접촉 감소" 가 아니라 **"명령된 |v_eff| 가 0.35~0.57 m/s 대역에 도달하는가"**.
도달 자체가 안 되면(게이트가 램프 중 깎으면) R1/R2 의 독립 효과는 0 이고 다음은 R5(게이트 수용성)다.

### R2.5 — 비용 함수를 후보 집합에 맞춰 다시 세운다 — **부분 완료**

**한 것**: 방출단 저크 이중 적용 제거(커밋 e029023), `tools/cost_probe` 오프라인 진단 루프,
`DwaDiag.term_span`(항별 가중 기여 폭).

**결과** (R25a·c·d 90 시행):

| | 기준선 | R2.5 | |
| --- | --- | --- | --- |
| 접촉 | 2 / 60 (3.3 %) | 2 / 90 (2.2 %) | Fisher **p = 1.0000** 구분 불가 |
| 통과 라운드 | 1 / 2 | 2 / 3 | 표본 부족 |
| `disp_span` 중앙 | 0.0774 | **0.8728** | 표현력 11 배 |

**판정**: 기제는 전부 개선되거나 중립이고 회귀가 없다. **그러나 명세 기준(접촉)에 대한 효과는
증명되지 않았다.** 이 표본으로는 원리적으로 증명할 수 없다(팔당 633 시행).

**그래도 켜 둔다.** 근거는 "개선이 증명돼서" 가 아니라 **"남은 항목들의 선행 조건이고 해가
측정되지 않아서"** 다 — R3·R4·R5 는 모두 후보가 구별된다는 전제 위에서만 의미가 있다.
후보 집합이 붕괴해 있으면 어떤 술어를 고쳐도 argmin 이 안 바뀐다.

**남은 것**: 비용 **가중치** 자체는 아직 재유도하지 않았다. `dynamic` 이 이제 37~41 % 를
차지하는데 그 값이 맞는지 검증된 적이 없다 (망가진 후보 집합에서 튜닝됐으므로).

### R2.6 — 비용 가중치 재유도 ← **지금 여기**

R1+R2 실측이 강제한 항목이다 (§4.6). 후보가 구별되기 시작하면 현 8 항 가중합이 느리고 도는
후보를 고른다. 먼저 고칠 것:

1. **`J_dyn`**: 속도가 아니라 **궤적이 실제로 얼마나 가까워지는지**로 벌해야 한다.
   램프 롤아웃에서는 `c.ttc = firstContactTime(pred, ...)` 가 후보마다 달라지므로,
   속도 excess 항을 버리고 ttc/최근접거리 기반으로 다시 세운다.
2. **가중치 재유도**: 지금 값은 아무것도 결정하지 않아서 살아남은 값이다. 후보가 구별되는
   상태에서 각 항의 기울기 크기를 실측해 균형을 다시 잡는다 (리서치의 "가로 방향 기울기로
   재면 경로항 2.5/m + 탈출항 1.91/m 대 J_dyn 0.09/m 로 49:1" 지적을 이제 검증할 수 있다).
3. 판정은 **R0 계측**으로 한다 — `|cmd_v|` 중앙이 기준선(0.88)에서 떨어지지 않으면서
   `disp_span` 이 0.8 대를 유지하는가.

**반증 조건**: 비용 함수를 고쳐도 `|cmd_v|` 가 회복되지 않으면 R1/R2 의 전제("후보를 넓히면
더 나은 선택이 가능해진다")가 틀린 것이고, R5(검증된 백업 = gatekeeper)로 넘어간다.

### R3 — 동적 하드 제약을 현(chord) 근사에서 참 호(arc) 접촉 판정으로

§3.2·§3.3 을 동시에 친다. v=0 에서 `chordVelocity ≡ (0,0)` 인 축퇴와 `pn2 < R*R` 조기 반환을 없앤다.

### R4 — `footprint_reach` 를 처음으로 배선 (방위 의존 기하)

죽은 코드를 살린다. 단 §4.1 로 **"84.8 %" 논거는 무효**이므로 기대 효과를 다시 유도해야 한다.

### R5 — 정지 백업을 검증된 회피 백업으로 (gatekeeper 식 커밋 궤적 필터)

§3.4 를 고치는 **유일한** 항목. 매 주기 "공칭 궤적 접두부 + 백업 기동 접미부" 를 짧은 유한
지평으로 전방 적분해 검증하고, 검증 통과 후보만 남긴다. 실패 시 직전 커밋 궤적을 계속 실행
→ recursive feasibility. **안전 게이트는 한 줄도 건드리지 않는다** (불변식 A).

### R6 — 창 중심 되먹임 정정 (독립, R1 과 병행 가능)

`dwa_controller.cpp:543` `v_last_ = res.v` 는 **게이트를 거치지 않은** 계획기 자신의 출력을 다음
주기 창 중심으로 되먹인다. 게이트가 0 으로 깎는 동안 모든 롤아웃이 반사실(counterfactual)이다.

### 별건 — 명세 "재계획하여 회피" (P0-1)

설계 워크플로 결과는 `scratchpad/design_replan.json`. 승자는 "TTC-gated re-admission" 이었으나
**반증자 2인이 모두 기각**했다. 핵심 결손:

- `TrackedObstacle.time_to_collision` 이 경로 기반인 것은 `/plan` 이 신선할 때뿐인데,
  **86 시행 중 73 %가 계획을 정확히 1회만 발행**하고 `plan_timeout` 은 5.0 s, 시행 중앙 26.0 s
  → **시행의 81 % 동안 TTC 로봇 모델이 직선 외삽**이다 (내가 로그로 실측).
- 임계 사다리 3.5/2.65 가 기하적으로 틀림 — 마킹이 경로에 닿는 것은 τ ≲ 1.25 s.
- `min_ttc="{min_ttc}"` 배선이 `test_bt_replan.cpp:139` 매니페스트를 깨서 4 인스턴스 중 2개 실패.

  를 직접 완화하므로 거부**.

자료가 그 전제를 기각했다 — R1/R2 를 먼저 한다.

> 정의해 놓고 그 안에서 `nearest_obs < R_vo` 비율을 물었다. 100 % 가 나왔고 "조기 반환이

## 10. VO 포화가 접촉의 근접 원인이다 — 전수 검정

§3.3.1 이 기제로 예측했던 것을 **접촉 전수**에서 검정했다. 이전까지는 일화 수준이었다.

### 10.1 접촉 직전 3 초

`stats_trial*.csv` 에 R0 열이 있는 실행의 접촉 **77 건** 전수.
"VO 포화" = `n_selectable == 0` 인데 `n_collision_free > 0` (충돌 후보는 없는데 선택 가능 후보가 0).

- **71 / 77 (92 %)** 에서 접촉 전 3 초 안에 포화가 나타난다
- 그 접촉들의 포화 주기 비율 중앙 **0.32**

### 10.2 기저율 — 노이즈가 아니다

| 구분 | 포화 주기 | 전체 주기 | 비율 |
| --- | --- | --- | --- |
| 접촉 있던 시행 | 1 902 | 120 545 | **1.58 %** |
| 무접촉 시행 | 142 | 232 917 | **0.06 %** |

**26배. χ² = 3179 (자유도 1, 임계 3.84).** 포화는 드물고, 일어나면 접촉이 따른다.

### 10.3 기제 — 내가 두 번 틀렸고 자료가 두 번 고쳐 주었다

**첫 번째 가설: "양보로 감속 → 창이 저속으로 내려감 → 전부 VO 안".**

> **정정 (이 반증 자체가 틀렸다).** 내가 "포화 접촉들의 `v_hi` 중앙값이 1.000 m/s 이므로
> 창은 붕괴하지 않았다" 고 적어 이 가설을 기각했는데, 그 통계는 **표집 모드가 다른 실행에
> 지배된다**. 포화 주기를 창 **폭**으로 가르면:
>
> | 모드 | 포화 주기 | `v_hi` 중앙 | `v_hi < 0.30` |
> | --- | --- | --- | --- |
> | 넓은 창 (`sustained_sampling: true`) | 1 839 | 1.000 | 1.3 % |
> | **1주기 창 (배포 모드)** | **205** | **0.337** | **46.8 %** |
>
> 지속표집 모드에서는 `dwa.cpp:145` 가 `hi = win.v_cap` 으로 **`v_hi` 를 정의상 1.0 에
> 고정**하므로 그 값에 로봇 속도가 담기지 않는다. 배포 모드만 보면 가설대로 저속이다.
> **다만 하위 기제는 여전히 틀렸다** — 창 *폭* 이 붕괴한 구간(MX1a t00 t=16.569~17.199,
> 14 주기 `v_lo == v_hi`)에는 포화가 **0** 이다. 뒤집는 것은 폭이 아니라 창의 **위치**다.

**두 번째 가설(부분적으로 틀림): "`‖p‖ < R_vo` 조기 반환이 후보 속도와 무관하게 전부 기각".**
반증: 포화 주기 1442 개 중 보행자가 `R_vo`(0.911 m) 안인 것은 **388 = 26.9 %** 뿐이다.
중앙 최근접은 **1.137 m** 로 `R_vo` 밖이다. 조기 반환은 포화의 1/4 만 설명한다.

**자료가 가리키는 것**: 나머지 73 %는 `R` 밖의 **정상 VO 원뿔 계산**이다. 후보가 살아남으려면

```
closing = p · (v_eff − v_obstacle) ≤ 0        (velocity_obstacle.cpp:48)
```

인데, `min_vel_x: 0.0` (nav2_params.yaml:105 "후진은 BackUp 복구 동작만") 이므로 DWA 는
**전진 후보만** 만든다. 보행자가 1.0 m/s 로 접근하면 `−p·v_obstacle > 0` 이고, 전진으로는
`p·v_eff ≥ 0` 이라 `closing > 0` 이 된다. 게다가 정지 후보는 `chordVelocity` 가 (0,0) 이라
(§3.2) 역시 `closing = −p·v_obstacle > 0` 로 기각된다.

즉 **보행자가 약 1.1 m 안에서 접근하는 동안, 도달 가능한 전진 속도 집합 전체가
VO^τ(τ = 2.0 s) 안에 들어간다.** 로봇에게 표현 가능한 탈출이 없다.

### 10.4 따라서 표적은 셋 중 하나(또는 조합)

1. **도달 집합을 넓힌다** — 후진 후보 허용 (`min_vel_x < 0`). `p·v_eff < 0` 을 만들 수 있는
   유일한 직접 수단이다. 지금은 복구 동작에만 맡겨 두었다.
2. ~~**τ 를 줄인다**~~ — **틀렸다. 단조가 아니다.** `dwa.cpp:736` 이 같은 파라미터를
   VO 절단 시간과 현(chord) 적분 지평 **양쪽**에 쓴다. τ 를 줄이면 현이 덜 휘어 더 정면이
   되므로, 정면 1.9 m 에서 τ=2.0 은 탈출이 있고(|v| 0.922) **τ=1.0 은 없다**.
   둘을 분리하기 전에는 τ 를 레버로 쓸 수 없다.
3. **포화 대비책을 고친다** — `dwa.cpp:947~1030` 은 이미 정교하지만, 접촉 시행에서
   포화율이 무접촉 시행의 26배라는 것은 **대비책이 그 상황을 못 구한다**는 뜻이다.

**아직 고르지 않았다.** 네 갈래 독립 조사와 적대적 반박이 진행 중이고, 그 결과로 정한다.
§4 의 교훈 — 한 각도만 보고 고쳤다가 두 번 파국이 났다.

### 12.4 남은 미달 — "원래 경로 복귀" 는 해석 문제이자 공학 문제

실패 6 건(S0a t15·t29, S0b t03·t07·t08·t13)은 **전부 첫 경로 기준에서만** 난다.

```
         dev_first 는 버려진 계획과 재므로 t=72.36 까지 0.15 m 밖 → 복귀 5.48 s
```

**임계 탓이 아니다.** 복귀 임계 `back` 을 0.15 → 0.30 으로 풀어도 6 → 4 건이다.

(시행 끝 이탈 0.015~0.023 m).

1. **해석 문제.** 명세 191행만 "**원래** 경로" 로 한정한다(190행의 "경로 이탈" 은 한정

   요구가 아니라 빠듯한 요구**다. 재계획이 "목표까지 최적" 만 보고 "원래 노선에 빨리
   합류" 를 보지 않는 것이 직접 원인이다.

따라서 해석으로 넘기지 않고 **합류를 빠르게 하는 쪽**을 먼저 본다 — 그러면 두 해석
모두에서 통과한다. 판정은 그 결과로 한다.

## 13. 180 시행 — S0 가 접촉을 줄였다 (이번엔 유의하다)

`logs/S0a` ~ `logs/S0f` (각 30 시행, HEAD `cebd351`).

### 13.1 S0f 는 측위 실패 실행이다 — 따로 센다

`S0f` 만 혼자 다르다. 로그 321행에서 **시행 시작부터** 나갔고 끝까지 못 돌아왔다:

```
[kidnap_monitor_node] [RECOVERING] LOST: scan registration rejected 20/20 (1.00 > 0.80)
[kidnap_monitor_node] [RECOVERING] global re-init #1        (총 8 회)
```

| 실행 | `loc_err_m` 중앙 | 최대 | > 1 m 시행 |
| --- | --- | --- | --- |
| S0a~S0e · MX1a/b · R0a · N8x | 0.012~0.016 | 0.025 | **0** |
| **S0f** | **8.587** | 15.386 | **30 / 30** |

측위가 8~15 m 어긋난 상태에서 잰 "경로 이탈"(15.441 m)·"복귀"(100.7 s)는 회피 거동이
아니라 **측위 오차를 잰 것**이다. 그래서 두 방식 모두로 집계하고, 어느 쪽으로도 결론이
바뀌지 않음을 보인다. **이것은 별건의 결함이고 기록해 둔다** — 6 실행 중 1 회 발생.

### 13.2 접촉

| 구성 | 시행 | 접촉 시행 | 비율 | 대조군 대비 |
| --- | --- | --- | --- | --- |
| **S0 전체** (S0a~S0f) | 180 | 1 | **0.56 %** | Fisher **p = 0.0255** |
| **S0 측위 정상** (S0a~S0e) | 150 | **0** | **0.00 %** (95 % 상한 1.98 %) | Fisher **p = 0.0145** |
| 대조군 (N8x·y·z, R0a·b) | 150 | 7 | 4.67 % | — |

**어느 쪽으로 세도 유의하다.** 그리고 더 직접적인 근거: 대조군 비율 4.67 % 가 참이라면
30 시행 무접촉 확률은 23.8 % 이고, **5 라운드 연속 무접촉 확률은 0.077 %** 다.
실제로 5 라운드 연속 무접촉이 나왔다.

### 13.3 명세 §4.7 현황 (측위 정상 150 시행)

| 조항 | 기준 | 측정 | 판정 |
| --- | --- | --- | --- |
| 30회 수행 시 충돌 0건 | 0 | **0 / 30 × 5 라운드** | **충족** |
| 회피 기동 시 경로 이탈 | ≤ 1.0 m | **0.883** | **충족** |
| 경로를 재계획하여 회피 | 동작 | 37 % (대조군 5 %) | **충족** |
| 회피 후 원래 경로로 복귀 (현재 경로 기준) | ≤ 5 s | **3.82** | **충족** |
| 회피 후 원래 경로로 복귀 (**첫** 경로 기준) | ≤ 5 s | **8.70** | **미달** |

**남은 미달은 하나뿐이고, 그것도 두 해석 중 엄격한 쪽에서만 난다** (§12.4).

### 13.4 왜 S0 가 들었는가 — 인과는 아직 완전하지 않다

S0 가 제거한 것은 **"A* start 차단 → follow_path 취소 → 제어 공백"** 사슬이고,
그 사슬은 `cost: 254` 를 쓴 실행에만 있었다(§11). 그런데 대조군(N8x·y·z, R0a·b)은
`admit_ttc: 0.0` 이라 그 사슬이 애초에 없다. 즉 **대조군의 접촉 7 건은 다른 원인**이다.

따라서 "S0 가 그 7 건을 고쳤다" 는 설명은 성립하지 않는다. S0 커밋은 두 가지를 동시에
바꿨다 — (a) 치명 금지 반경, (b) `admit_ttc` 0.0 → 2.5(재계획 켬). **둘 중 어느 쪽이
들었는지는 아직 분리되지 않았다.** MX(= 재계획만, S0 없음)가 3.33 %, S0(= 둘 다)가
0.00 % 이므로 (a) 쪽이 유력하지만 MX 는 60 시행뿐이고 그 차이는 p = 0.4958 이다.
분리하려면 `lethal_keepout: 0.0` 으로 되돌린 팔을 같은 시행 수로 돌려야 한다.

## 14. 절제 실험 — 두 변경의 기여를 가른다 (450 시행)

§13.4 에서 "S0 커밋이 (a) 치명 금지 반경과 (b) 재계획을 동시에 바꿔 분리가 안 된다" 고
적었다. `lethal_keepout` 만 0.0 으로 되돌린 팔(`logs/ABLa~ABLc`, 90 시행)을 돌려 갈랐다.

### 14.1 기제 — keepout 이 `start blocked` 를 인과적으로 제거한다

| 팔 | 시행 | `start blocked` | 그 사건이 있는 라운드 | `Goal was canceled` |
| --- | --- | --- | --- | --- |
| `lethal_keepout: 0.46` (S0a~S0e) | 150 | **0** | **0 / 5** | **0** |
| `lethal_keepout: 0.00` (ABLa~c) | 90 | **10** | **3 / 3** | 3 |

다른 설정은 전부 같다. **이것은 추론이 아니라 절제로 확인된 인과다.**

### 14.2 접촉 — 세 팔 분해

| 팔 | 구성 | 시행 | 접촉 시행 | 비율 |
| --- | --- | --- | --- | --- |
| **A** | 재계획 끔 (`admit_ttc: 0.0`) | 150 | 7 | 4.67 % |
| **B** | 재계획 켬 · keepout 없음 (ABL + MX) | 150 | 3 | 2.00 % |
| **C** | 재계획 켬 · keepout 0.46 (S0a~S0e) | 150 | **0** | **0.00 %** (95 % 상한 1.98 %) |

| 비교 | Fisher p |
| --- | --- |
| A vs B | 0.3354 |
| B vs C | 0.2475 |
| **A vs C** | **0.0145** |
| **추세 (Cochran–Armitage)** | **z = −2.74, p = 0.0061** |

**정직한 결론**: 두 변경 중 **어느 쪽도 단독으로는 유의하지 않다**(각각 150 시행으로는
검정력이 부족하다 — §2 가 적은 633 시행 요건 그대로다). 그러나 **세 팔의 단조 감소는
유의하고**(p = 0.0061) **양 끝 비교도 유의하다**(p = 0.0145). 즉 "둘 다 기여하며,
개별 기여를 이 표본으로는 가를 수 없다" 가 자료가 지지하는 전부다.

`start blocked` 쪽은 다르다 — 0/150 vs 10/90, 라운드 0/5 vs 3/3 이라 **기제 수준에서는
keepout 의 효과가 확정**이다. 접촉 감소가 그 기제를 **통해서** 일어났는지는 미확정이다.

## 15. 복귀 판정을 사전 등록 정의로 되돌린다 — 그리고 그 결정의 근거

§12.4 에서 "복귀(첫 경로) 미달은 해석 문제이자 공학 문제" 라 적고 A* 에 경로 연속성 항을
넣으려 했다. **그 전에 네 갈래 조사 + 적대적 반박을 돌렸고, 결론은 "하지 마라" 였다.**
아래 근거는 전부 내가 독립적으로 재확인했다.

### 15.1 명세는 이 정의를 넘겼다

명세 §10 "성능 지표 측정 절차 표준화" 표(249~254행)의 행은 **네 개뿐**이다 —
위치 추정 RMSE · 경로 추종 CTE · 응답 시간 · 테스트 커버리지.
**'경로 이탈' 과 '복귀 시간' 행이 없다.** 조작적 정의가 구현자에게 넘어왔다.

§9 체크리스트가 §4.7 에 대해 묻는 것은 556행 하나다:
`- [ ] 동적 장애물을 추적하고 예측 기반 회피가 수행되는가?(30회 테스트 충돌 0건 확인)`

### 15.2 이 저장소는 그 재량을 **9 일 전에** 행사했다

| 출처 | 내용 | 커밋 | 시각 |
| --- | --- | --- | --- |
| `docs/architecture/sequences.md:216` | 복귀 5 s·이탈 1 m 를 **CTE 로그**로 묶음 | `99d4ffd` | **09-22 03:32** |
| `src/amr_evaluation/amr_evaluation/cte_logger.py:7` | "**최신** 계획 경로" 기준 | `4601871` | **09-22 11:16** |

내가 "두 기준 모두 통과해야 한다" 로 강화한 것은 **10-01** 이다. 사전 등록이 먼저다.
순서가 반대였다면 §4 가 금지한 "유리한 기준으로 갈아타기" 였을 것이다.

### 15.3 엄격 기준은 일관 적용이 **불가능**하다 [150 시행 전수, 내가 재계산]

| 기준 | 이탈 > 1.0 m | 복귀 > 5 s | 이탈 최대 | 복귀 최대 |
| --- | --- | --- | --- | --- |
| **활성 계획** (사전 등록) | **0 / 150** | **0 / 150** | **0.883** | **3.82** |
| 첫 계획 (자가 강화) | 32 / 150 | 11 / 150 | 7.064 | 8.70 |

같은 기준을 190행(이탈)에도 쓰면 32 건이 터지고 최대가 7.064 m 가 된다. 그런데 그 시행에서
무슨 일이 있었는지 보면:

```
S0d t12 — 계획 5 회 교체
  계획 0 채택 t=199.10 (-3.99, -5.01)   dev_first 0.020   dev_cur 0.020
  계획 4 채택 t=205.98 (-1.86, -7.92)   dev_first 2.130   dev_cur 0.003
  최대       t=212.80 (-1.84,-13.11)   dev_first 7.064   dev_cur **0.007**
  판정: 도달 O · 접촉 0 · 최근접 0.330 m · 소요 25.1 s
```

**로봇은 한 번도 경로를 벗어나지 않았다.** 다른 노선으로 우회했고 그 노선을 7 mm 오차로
따라갔다. "경로에서 7 m 벗어났다" 는 서술은 사실이 아니다.

### 15.4 엄격 기준은 "회피의 질" 이 아니라 "재계획 여부" 를 잰다 — 완전 분리

| | 재계획함 (55) | 재계획 안 함 (95) |
| --- | --- | --- |
| 첫 계획 기준 이탈 > 1 m | **32** | **0** (최대 0.439) |
| 첫 계획 기준 복귀 > 5 s | **11** | **0** (최대 3.82) |
| 활성 계획 기준 이탈 > 1 m | 0 | 0 |

명세 181행이 재계획을 **의무화**하는데 190·191행이 그것을 벌점하는 구조가 되므로,
첫 계획 읽기는 명세를 자기모순으로 만든다. 활성 계획 읽기는 그렇지 않다.

### 15.5 그리고 고치려던 것은 위험했다

연속성 항은 정의상 **"장애물이 방금 있던 자리" 쪽으로 경로를 당기는 힘**이다. 지금 가장
깨지기 쉬운 것이 방금 닫은 접촉 0/150 이고, 그 회귀를 판정하려면 팔당 633 시행이 필요하다
(§2). **자가 강화 지표 하나를 위해 충돌 0건 조항을 걸 수 없다.** A* 는 06·07·11·12·13·14 가
전부 공유하고 지금 12/14 가 통과 중이다.

조사가 내놓은 1 위 설계안의 핵심 수치("λ=0.05 에서 8.56 s → 2.50 s")도 반박에서 무너졌다 —
실제로 존재하지 않는 재계획 시점에서 잰 값이었다.

### 15.6 조치

- 판정을 **활성 계획 기준으로 일치**시킨다 (이탈·복귀 모두).
- `max_dev_first_m` · `return_first_s` 는 **전 시행에서 계속 기록**하고 요약에도 싣는다.
  숨기지 않는다 — 누구나 이 두 열로 이 결정을 재검증할 수 있어야 한다.
- 리포트에 두 정의와 그 차이를 명시한다 (명세 248행이 넘긴 재량을 명시적으로 행사).
- **A* 는 건드리지 않는다.**
