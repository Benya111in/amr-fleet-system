# 서버 없는 협상 할당 코어 (CBAA) — 구현과 오프라인 파라미터 결정

보너스 4 P2. 명세 5장 4번 "로봇 간 직접 통신을 통한 협상 기반 작업 할당을 구현한다" 의 알고리즘
코어다. 설계 근거는 보고서 「분산 플릿 관리 협상 할당과 폴백」 19–73행(채택안)과 218–276행(P2) 이다.
이 문서의 수치는 모두 **[계산]** 이다 — 오프라인 파이썬 시뮬레이터의 결과이고 Gazebo·실물 측정이 아니다.

## 0. 먼저 적어 둘 한계

- **ROS 통합이 없다.** `amr_fleet/negotiation/` 은 rclpy 를 쓰지 않는 순수 모듈이다. 노드·메시지·BT 결합은
  P3(다음 물결) 몫이다. 이 문서의 "라운드" 는 동기 라운드 모형이고, 실제 ROS 실행기의 비동기 수신·처리 지연은
  들어 있지 않다.
- **작업 ID 정족수 잠금은 인터페이스와 가짜 구현뿐이다.** "엄격 모드" 의 중복 0 은 `ExclusiveTaskLock`
  (프로세스 안 공유 표 = 과반 연결이 유지되는 이상적 정족수 잠금) 을 가정한 결과다. f1 의 `vote_core` 와
  묶으면 분할·소수쪽 로봇은 잠금을 못 얻어 진행이 멈추는데, 그 대가는 여기서 재지 않았다.
- **낙관 모드(잠금 없이 국소 확정만)는 버스트 손실 0.2 에서 중복이 0 이 아니다** (0.1–0.2 %, 5.3 절). 독립
  손실에서만 0 이다. 그래서 잠금 없는 운용은 제안하지 않는다.
- 손실 모형의 한계: Gilbert 버스트 상태는 시간이 아니라 **메시지마다** 진행하고 링크끼리 독립이다 (노드 단위 간섭
  버스트가 없다). `ExclusiveTaskLock` 은 요청 로봇의 연결 상태와 무관하게 허가하므로 엄격 모드의 확정 지연(5.1)과
  품질(5.2)은 낙관 쪽 값이다.
- 0 건 결과는 사례 1,000 회에서 0 이라는 뜻이고 단측 95 % 상한은 0.3 % 다 (rule of three). "절대 0" 이 아니다.
- 비용은 이동 시간 추정뿐이다. 보고서 54행의 우선순위 가중 점수 W(priority)·λ^T 와 후보 상위 k 제한은 넣지 않았다.

## 1. 구현

위치: `src/amr_fleet/amr_fleet/negotiation/` (기존 `allocation.py` 는 import 만 한다).

| 모듈 | 내용 |
|---|---|
| `bids.py` | 입찰(비용, 승자), `NO_BID`, 잠금 표시 `LOCKED_COST = -inf`, 비교(비용 → robot_id 사전순), 방송 상태 `StateMessage` |
| `consensus.py` | 수신자 병합 규칙 `'max'`(CBAA Alg. 2 최대 합의) · `'cbba'`(CBBA 표 1 의 update/reset/leave 17 칸, L_t = 1) |
| `agent.py` | `CbaaAgent` — 로봇 1 대의 상태기계, `AgentConfig`(+ `strict_mode()` · `optimistic_mode()` 제안값) |
| `task_lock.py` | `TaskLock` 추상 클래스(GRANTED / PENDING / DENIED), 가짜 `OptimisticTaskLock` · `ExclusiveTaskLock(grant_delay)` |
| `cost.py` | `EuclideanCost` = `allocation.travel_time(approach_distance(...))` (중앙 Hungarian 과 같은 값), `GridAstarCost` |
| `grid.py` | `maps/warehouse.yaml` PGM 적재 → 칸 축소(화소를 버리지 않는다 — 위·오른쪽 나머지 띠도 칸, 지도 밖은 미지) → 팽창 → 8-이웃 A*(모서리 자르기 금지, 칸 쌍 기억) |
| `channel.py` | 링크별 파생 난수 `PerLinkChannel`(Bernoulli 또는 Gilbert 버스트, U(0, 100) ms, 링크 분할), 재현용 `SharedStreamChannel` |
| `scenario.py` | 도크 4곳·스폰 5곳(저장소 좌표), 사례 생성기, 중앙 탐욕(SGA) · Hungarian 기준 |
| `sim.py` | 동기 라운드 시뮬레이터, 이탈·건강 저하 주입, 중복·미할당·고착·이어받기 라운드 |
| `sweep.py` | `python3 -m amr_fleet.negotiation.sweep --out-dir DIR` — 실험 10 종, 셀별 CSV |

한 라운드(주기 T_b) 순서는 연구 계산과 같다.

1. `start_round` — 쥔 작업이 없고 위치추정이 건강하면, 지금 표에서 이길 수 있는 가장 싼 작업에 입찰 (L_t = 1)
2. `make_message` — **전체 상태**를 방송: 작업별 승자 입찰, 출처별 최신 시각(CBBA 의 s), 건강 플래그, 잠금
3. `receive` — 병합 규칙으로 합친다. 잠금(LOCKED) 입찰은 시각 비교 없이 받아들이고 더 나은 잠금으로만 바뀐다
4. `finish_round` — 하트비트·건강 무효화 → 패배 판정 → K 라운드 안정 계수 → (선택) 이번 라운드 생존 로봇 전원
   직접 수신 → `TaskLock.try_acquire` → GRANTED 면 실행 시작, 그 작업을 LOCKED 로 방송 (비선점)

- **하트비트 무효화**: H 라운드 넘게 소식이 없는 로봇의 낙찰(잠금 제외)을 지운다. 생존 판정은 `'indirect'`
  (출처별 최신 시각 — 다른 로봇이 중계한 소식 포함, 기본) 또는 `'direct'`(직접 수신만).
- **위치추정 건강 게이트**: 건강이 나빠지면 입찰하지 않고, 실행 전 낙찰은 철회한다. 받는 쪽은 건강이 나쁘다고
  알린 로봇의 낙찰을 무효화한다. 실행 중 작업은 건드리지 않는다 (픽업 뒤 고장은 실행기·운영자 몫).
- **잠금 거절**: DENIED(보유자 h)면 그 작업을 `LOCKED(h)` 로 표시하고 다음 라운드에 다른 작업에 재입찰한다.
  보유자를 모르면 그 작업을 막아 둔다.

## 8. 다음 물결에 넘길 것

- **잠금 결합**: `TaskLock.try_acquire` 는 폴링형(GRANTED/PENDING/DENIED)이고 f1 의 `ZoneAgent` 는
  `request(resources, now) → [메시지]`, `may_enter(resource)`, `release(...)` 의 메시지형이다. 어댑터가 송신함을
  가져야 하고, 자원 이름 공간(`task:<id>` 등)과 "DENIED 일 때 보유자" 를 무엇으로 알 수 있는지 맞춰야 한다.
  `ZoneAgent` 는 활성 시도가 1 개라 L_t = 1 과 맞는다.
- **메시지**: `StateMessage` 필드(sender, stamp, bids{task: (cost, winner)}, info_time, healthy, assigned,
  executing)를 ROS 메시지로 옮길 때 f1 의 `VoteMsg` · f2 의 TLA+ 상태 이름과 나란히 정한다. 잠금 표시는 지금
  `cost = -inf` 인데 메시지에서는 별도 필드가 낫다.
- **후보 제한·점수**: 보고서 54행의 (우선순위 ↓, 마감 ↑) 상위 k 후보와 W(priority)·λ^T 점수가 없다. 지금은
  호출자가 넘긴 작업 전부가 후보이고 비용은 접근 시간뿐이다.
- **온라인 도착**: 사례마다 작업이 한 번에 주어진다. 작업이 실행 중에 들어오고 끝나는 흐름(`set_tasks`)은 단위
  시험만 있고 스윕하지 않았다.
- **확정 창**: 전원 직접 수신을 "이번 라운드" 대신 "최근 W 라운드 안" 으로 넓히는 변형은 재지 않았다.
- **시각 계약**: `CbaaAgent.heard_all_alive` 는 `last_direct == now` **정확 일치**로 "이번 라운드에 직접 받았다" 를
  판정한다. ROS 노드가 `now` 에 수신 시각(sim-time 초)을 넘기면 라운드 끝 시각과 달라 전원 수신 확정이 영원히
  나지 않는다. 결합 때 `receive`·`finish_round` 에 **같은 라운드 식별자**(라운드 번호 또는 라운드 시작 스탬프)를
  넘긴다는 계약을 지켜야 한다.
- **잠금 거절의 막힘**: 보유자를 모르는 DENIED 를 받으면 그 작업을 `blocked` 에 넣고 **풀지 않는다**. 실제 정족수
  잠금에서는 이 거절이 일시적일 수 있으므로(표 갈림) 기한·재시도가 필요하다. `TaskLock` 에는 보고서의 "잠정 표 +
  기한 갱신 → 픽업 시 확정" 2 단계도 없다.
- **동점 처리**: 입찰 동점은 robot_id **문자열** 사전순이고 중앙 탐욕은 로봇 목록 번호 순이다. 저장소 이름처럼
  0 을 채운 두 자리(`amr_01`…`amr_05`)면 둘이 같지만, `amr_9`·`amr_10` 처럼 자릿수가 다르거나 100 대를 넘으면
  어긋난다 (`'amr_10' < 'amr_9'`). 메시지로 옮길 때 정수 ID 비교가 낫다.
- **두 계층 지연**: 동기 라운드 모형에는 노드 처리 지연·실행기 순서가 없다. P4 운동학 계층에서 다시 재야 한다.
