## 가설과 예측
관찰 (W-regress2 실패 메시지, 원자료는 컨테이너 임시 디렉터리라 남지 않음): amr_05 가 첫 작업(0100)을 sim 117.0 에 픽업(분할 시작
118 직전), 분할 중 amr_05 의 새 낙찰이 없다 (task_granted amr_05: 0100 @108.8, 0102 @162.4). P3 판정 실행 P3R_part_s1–3 (`36f190c`)
에서는 셋 다 amr_05 가 첫 작업을 ~116 에 픽업한 뒤 **119.0–119.4 에 0x05 를 낙찰**받아 ~137 에 픽업했고 이것이 "다수 쪽 분할 중
픽업 1" 이었다. 그러니 W-regress2 에서 빠진 것은 "분할 중 amr_05 의 두 번째 낙찰" 이다.
- H1 (b4-wire 의 낡은 LOCKED 정리 — 노드 기본 `nego.stale_lock_gc: true`, P3 에는 없음): 정리가 가짜 실행기 경로의 협상을 바꿔
  amr_05 의 두 번째 낙찰을 막는다 (예: 바쁜 동안 받은 낙찰 · 남의 잠금을 지우는 시점). 예측: B(HEAD)는 공허 실패가 잦고
  C(HEAD + 정리 끔)와 A(기준)는 드물다; B 의 사건 로그에 분할 전후 `stale_lock_cleared` 가 있다.
- H2 (시각 흔들림): 다수 쪽 두 번째 낙찰의 성립이 공유 부하 · 손실 난수 · 분할 경계 시각에 민감하고 기준에도 실패가 있다.
  예측: A · B · C 모두 가끔 실패, 팔 사이 차이는 n 4 로 가르지 못함.
- 판정 규칙 (n = 팔마다 4, 같은 시험 기본 시드 1 · 손실 0.2 — 실행 사이 차이는 시각뿐):
  - B 공허 실패 ≥ 3/4 이고 A ≤ 1/4 → b4-wire 변경이 원인으로 본다. 이때 C ≤ 1/4 이면 정리(H1)가 원인, C ≥ 3/4 이면 다른 변경.
  - A · B 모두 ≤ 1/4 또는 모두 ≥ 2/4 → "가르지 못함" (H2 쪽 — 공허 검사가 시각에 민감). 그 경우에도 기전은 사건 로그로 적는다.
  - 그 밖(예: B 2/4 · A 0/4) → 판정 불가로 적고 n 을 늘릴지 다음에서 정한다 (결과 뒤 변경으로 적는다).
  - 안전 단언(소수 쪽 분할 중 픽업 0 · 중복 0)이 한 번이라도 깨지면 이 진단과 별개로 **안전 결함**으로 먼저 적는다.
  - 표본 4 는 비율 추정이 아니다 — 큰 차이(3/4 대 0/4 수준)만 가른다.
