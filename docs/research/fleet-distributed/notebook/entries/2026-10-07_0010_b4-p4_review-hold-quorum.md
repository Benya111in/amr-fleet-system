## hold 모드 설계 (코드 `fleetsim/central.py` · `robot.py`, 현행 코드와 맞춘 것과 다른 것)

| 항목 | 모형 | 현행 근거 |
|---|---|---|
| hold 값 | 토큰 요청이 이번 주기에 허가되지 않은 로봇만 true, 나머지 관측된 로봇(stale · lost 포함, 요청이 없다)은 false | `traffic_manager._compose` 토큰 hold, `_tokens`(stale 은 경로 없음 → 요청 없음) |
| 송신 | 값이 바뀔 때만, 신뢰 경로(유실 시 0.2 s 재전송), seq 로 옛 값 무시 | `traffic_manager_node._apply` `hold != r.hold`, `LATCHED_QOS` RELIABLE/TRANSIENT_LOCAL |
| 초기값 | 내지 않는다, 처음 평가한 값을 낸다 · 관측 못 한 로봇은 3 s 뒤 false | D5 · D6 |
| 로봇 | 첫 값 전 대기, 마지막 값 유지(서버 사망에도), true 면 그 자리에서 최대 감속 1.0 m/s² 로 정지 | D2 · D4, 실행기 hold → 주행 goal 취소 |
| 넣지 않은 것 | 교차 예측 hold, 사건(양보 · 포켓) hold — 허가 목록 모형과 같다 | p4.md §1 한계 |

허가 목록 모형과의 차이는 두 가지가 섞여 있다: (a) 게이트 의미(허가 목록 대 거부 목록), (b) 송신(매 주기 상태 대 바뀔 때만
신뢰 경로). 둘 다 "현행에 더 가까운 쪽" 이라 함께 바꿨다 — 효과를 둘로 가르지 않는다.

- **P1 은 hold 의미에서도 성립한다** (+15.4, 30/30). 다만 크기는 허가 목록 기준 +17.8 보다 2.4 건 작다 — 1 차 수치의 일부는
  모형(fail-closed)이 만든 것이었다.
- **"현행은 충돌 뒤 구역 허가가 멈춘다" 는 현행이 아니라 허가 목록 모형의 성질이었다.** 현행 의미에서는 hold=false 로봇이 관리
  없이 진행 중 작업을 끝내고(+2.5 건), 그 대가로 서버 충돌 뒤 30 실행 중 12–13 실행에서 다른 로봇이 있는 도크 구역에 완전히
  들어갔다. 분할(F5)에서는 소수쪽이 관리 없이 움직여 19–29/30 실행에서 같은 일이 생겼다. 리뷰 근사(2/30)보다 많다 — 리뷰 근사는
  앞에 아직 허가받지 않은 구역이 하나라도 있으면 세웠다.
- **hold(거부 목록) 의미는 서버가 살아 있어도 도크 구역을 다 지키지 못한다.** 손실 0 · 무장애에서도 A1h 6/30, A5h 14/30 실행이
  도크 구역에 얕게(≤ 0.18 m) 들어갔다. 기제는 p0.md §5 가 계산한 "도크 구역 요청 거리 1.5 m < 결정점 거리 1.85 m" 와 같다:
  거절 hold 가 왔을 때 이미 멈출 수 없는 거리였다(침범 로봇 6/6 이 hold=true). 같은 쪽 두 도크 사이에서는 "구역 안에서는
  묶이지 않은 다음 구역을 요청하지 않는다" 규칙 때문에 요청이 더 늦다(스모크 추적). 허가 목록은 정지선을 미리 알고 감속하므로
  이 위험을 가린다. 서버가 살아 있는 동안(F0) 손실 0 에서 결정점 거리를 지키는 교차로 · 통로 구역 사건은 A1h · A2h · A5h 모두
  0 이다 (서버가 죽은 뒤 A5h 는 관리 없는 교차로 통과로 13–15/30 실행에서 도크 밖 사건도 냈다).
- **1 차 2×2 의 "한쪽만 분산하면 못 이어 간다" 는 처리량에 대해서는 모형이 만든 결과였다.** hold 의미에서 처리량을 잇는 것은
  할당 분산(협상)뿐이고(할당 효과 +15.4, 교통 효과 0), 교통을 투표로 바꾼 칸(CV · DV)만 동시 점유 0 이다. 바른 문장은
  "처리량은 협상이, 서버 사망 뒤의 안전은 투표 교통이 지킨다" 이다.
- 손실 결과(0.05–0.4)는 관측 · hold 가 모두 같은 손실 링크를 지난다는 모형 가정에 달려 있다. 현행 코드에서 CommEmulator 는
  assign_task · robot_state 만 모의하므로, Gazebo 기본 구성에 대응하는 것은 **손실 0 칸**이다.
- 이 항목이 말하지 않는 것: 실제 차체 · Nav2 제동에서의 침범 깊이(여기 정지는 1.0 m/s² 이상화, 실행기 취소 → 정지 지연 0),
  교차 예측 hold · 사건 hold 가 도크 앞에서 더해 주는 보호, 침범이 물리 충돌로 이어지는지. 침범 깊이는 상자 겹침이지 충돌이 아니다.
