## 해석

- P1 은 이 모형에서 매우 강하다(30/30, d_z 5.2): 서버가 죽으면 현행은 구역 허가와 할당이 함께 멈추고, 제안 설계는 F0 과 같은
  처리량을 유지한다. 2×2 가 보여 주듯 **할당과 교통을 둘 다 분산해야** 효과가 있다 — 한쪽만 분산하면 거의 0.
- 평상시 비용(P3·P4)은 손실 ≤ 0.2 에서 ±1.5 s 안이다. 손실 0.4 에서만 투표 교통이 +4–7 s 느리다 (재전송 0.5 s · 표 갈림 백오프).
- 할당 방식 비교(보고서의 7 비교군 축)는 이 작업 열에서 거의 정보가 없다 — 중앙 셋이 같고, CBAA 는 +1–2 s.
  할당 품질 차이를 보려면 묶음 도착(동시 다건)이나 더 높은 부하가 필요하다 (다음).
- 안전 0 건은 **이 모형의 게이트·투표·토큰 결합**이 맞다는 증거이고, 실제 차체의 제동·위치추정·별칭은 범위 밖이다.
- 낙관 모드의 중복은 손실이 아니라 **분할**에서 생겼다 (소수쪽이 같은 작업을 확정하고 분할이 풀린 뒤 둘 다 적재). 엄격 잠금이
  막는다. 분할 중 소수쪽은 구역 표도 못 얻어 도크에 못 들어가므로, 중복은 분할이 풀린 뒤에 나타난다.

  작업을 끝낸다 (A1h F1 완료 6.10–6.17, A1 3.63–3.73).
- P1 은 유지된다: **A9 − A1h +15.4 [14.0, 16.7], 30/30, 우월** (허가 목록 기준 +17.8 보다 2.4 작다).
- 2×2 "할당과 교통을 둘 다 분산해야 효과가 있다" 는 처리량에 대해서는 모형이 만든 결과다. hold 의미 2×2(CC A2h · DC A5h)에서
  F1 처리량 효과는 할당(+15.4)뿐이고 교통 효과는 0 이다. 투표 교통이 하는 일은 서버 사망 뒤의 **안전**이다 (CV · DV 동시 점유
  0, CC 13/30 · DC 30/30 실행).
- 탐색 "F5 손실 0.4 에서 분산 비교군이 현행보다 나쁘다" 도 허가 목록 A1 기준이다. A1h 기준(사후)으로는 F5 지연 차가 손실 0
  에서도 +16–18 s 로 커진다 — A1h 소수쪽이 관리 없이 움직이는 값이라 "현행이 빠르다" 가 아니라 "현행은 안전을 내주고 빠르다" 다.
