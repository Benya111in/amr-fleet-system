### 2.1 명세에 없는 우리 문턱

아래는 **명세 수치가 아니라 우리가 정한 판정 기준**이다. 시나리오가 이 기준으로 실패해도 명세
미달과 같지 않다.

| 우리 문턱 | 값 | 어디 | 명세에 있는가 |
| --- | --- | --- | --- |
| map↔월드 SE(2) 정합 | 이동 ≤ 5 cm, 회전 ≤ 0.1°, 거리 중앙값 ≤ 5 cm | `amr_itest/cases.py:328` | 없음 (명세는 해상도 0.05 m 만) |
| 지도 구조물 재현율 / 오점유 | ≥ 0.90 / ≤ 0.05 | `test_03:32-33` | 없음 ("맵 품질 지표를 정의하고 측정" 만) |

| 08 이탈 측정 범위 | 시행 **전체** 최대 (첫 계획 기준) | `test_08:407-409` | 명세는 "**회피 기동 시**" 로 한정 — 우리 쪽이 **더 엄격** |

| BT 복구 시한 | 60 s | `test_11` | 없음 |
| 소크 실패율 / 누수 | ≤ 2 % / 5 MB·h⁻¹ | `test_14` | 실패율은 없음, 누수 기준도 우리 것 |

**03 이 reg2 에서 실패한 것은 이 표의 첫 줄 때문이다** — 정합 이동 5.91 cm 가 우리 문턱 5 cm 를
넘었다. 회전 0.0472°, 거리 중앙값 1.34 cm 는 통과했고, 명세가 요구하는 해상도·품질 지표도
통과했다.

**커버리지 범위**: 95 %는 `colcon coveragepy-result` 의 Python 문장 커버리지다. C++ 패키지는
gtest 로 시험하지만 gcov 를 구성하지 않아 줄 커버리지 수치가 **없다**. 명세는 "주요 모듈"
70 % 를 요구하는데 DWA·A*·EKF·BT 는 C++ 이므로, Python 만으로 충족했다고 적을 수 없다.

## 4. 미달·열린 항목

### 4.1 시나리오 07·08 — 같은 결함 (최대 현안)

두 시나리오의 실패가 **같은 기제**임이 reg2 에서 드러났다.

07 은 직선 CTE 평균이 16.96 cm 로 기준 5 cm 를 넘었는데, **중앙값은 0.85 cm** 로 정상이다. 나쁜
표본은 t=41.78~51.74 s 의 **단일 연속 구간**에 몰려 있고(직선 표본의 14.4 %), 그 정점에서:

```
t=49.22~49.94   계획점 (8.07, 5.66) 고정
                실제   (7.86, 6.87) 고정   cte = −1.231
```

**로봇이 경로 밖 1.23 m 지점에 멈춰 서 있다.** 07 은 `use_perception=True` 로 돌아 회피 로직이
살아 있고, 08 에서 관측한 서명과 같다 — 탈출(escape) 이득이 로봇을 통로 축에서 밀어내고, 안전
게이트가 속도를 깎아 그 자리에 정지한다. 09-27 실행에서 07 의 최대 이탈은 0.2988 m 였다.

08 실측 (150 시행):

| --- | --- | --- | --- |
| y8a | 1 | 0.840 | **5.34** |
| y8b | 0 | **1.039** | **6.54** |
| y8c | 1 | 0.907 | 3.88 |
| y8d | 1 | 0.751 | **5.36** |

접촉 6/150 = 4.0 %. 실패는 무작위가 아니라 **시행 번호에 잠겨 있다** — 108 회 실행 3,240 시행
집계에서 시행 8 이 20.4 %, 0 이 16.7 %, 6 이 12.0 %, 11 이 9.3 %, 22 가 8.3 % 이고 시행 25 는

문제다.

대응: 노출 구간 **밖**에서 진입 **전**에 판정하는 횡단 게이트(`crossing_gate.cpp`, 파라미터
`yield_gate`). 대기를 경로 **위**에서 하므로 이탈이 0 이고 복귀 판정이 발생하지 않는다. 계약
71 개(기존 55 + 신규 16) 통과. **Gazebo 측정 전이다.**

### 4.2 명세 "재계획하여 회피" 와 현 구현의 차이

명세 181 행: *"1.0m/s 속도로 움직이는 동적 장애물을 인식하고 **경로를 재계획(Replanning)하여
회피**해야 한다."*

인식은 충족한다 (worker_crossing 1.0 m/s, reg2/08 조우 24/24, `is_dynamic` 확정 0.39~0.40 s).
**재계획은 일어나지 않는다** — 전역 코스트맵이 동적 트랙을 입력에서 뺀다
(`nav2_params.yaml` `exclude_dynamic: True`). 회피는 전적으로 지역 계획기(DWA)와 VO 가 한다.

이 설계를 택한 이유는 하네스가 시행 **첫 계획** 기준으로 이탈을 재기 때문에 재계획이 그대로
"이탈" 로 계상되어서다 (TTC 유발 재계획을 켰을 때 이탈 1.913 m). 명세 문구와 우리 측정 방식이
충돌하는 지점이고, **아직 해소하지 못했다.**

### 4.3 주행 시간 예측 오차 20.5 % (기준 15 %)

`docs/algorithms/dwa.md:464` — 무작위 쌍 8 구간 NavigateToPose (계획 경로 합 269~271 m):
DWA 평균 5.7 % / **최대 20.5 %**, DWB_E 8.2 / 20.1 %, TEB 14.0 / 34.4 %. 어느 통합 시나리오도
이 지표를 판정하지 않는다 — 측정은 있으나 회귀에 걸려 있지 않다.

### 4.4 C++ 줄 커버리지 없음

gcov/lcov 산출물이 저장소에 0 건이다. 명세는 "주요 모듈 70 %" 를 요구하는데 DWA·A*·EKF·BT 는
C++ 이므로 Python 95 % 만으로 충족했다고 적을 수 없다. gtest 로 시험은 하지만 줄 커버리지
수치가 없다.

## 5. 마커 기반 재위치추정 (신규)

도킹 서버가 **다른 도크의 마커**를 보면 (`perception/dock_marker_id` 가 기대 id 와 다르면) 그
마커의 지도 자세로 로봇 자세를 역산해 `localization/marker_fix` 로 낸다:

```
T_map_base = T_map_marker ∘ (T_base_marker)⁻¹
```

`kidnap_monitor_node` 는 이 자세가 현재 추정과 1 m 이상 어긋나면 LOST 를 선언하고 그 자세를 AMCL ·
map EKF 에 시드한다 (전역 가설 탐색을 건너뛰므로 별칭 가설로 다시 수렴할 위험이 없다). 오검출로
위치 추정을 흔들지 않게 6 m 이내에서 연속 3회 관측이 0.30 m 안에 들어올 때만 내고, 공분산은 거리에
비례해 키운다. 실측(시나리오 11): 3.18 m 에서 마커 0 을 보고 자세 (−27.12, 15.65, −168.8°) 를
σ 0.16 m 로 발행 → 14.3 s 만에 수렴.

## 6. 재현 방법

```bash
# 전체 (14 제외)
docker run --rm --gpus all --shm-size=8g -v "$PWD:/ros2_ws" amr-fleet-system:wf-final \
  bash -lc 'cd /ros2_ws && ./scripts/run_integration.sh --timeout-scale 2'

# 개별 (예: 08 동적 장애물 30 시행)
./scripts/run_integration.sh --domain-id 44 --timeout-scale 2 8

# 응답 시간 50 표본 · 5대 교착은 시나리오 상한을 늘린다
./scripts/run_integration.sh --scenario-timeout 7200 13
./scripts/run_integration.sh --scenario-timeout 5400 12

# 4시간 연속 운용
./scripts/run_integration.sh --include-long --soak-hours 4 14
```

단위 테스트·커버리지는 `./scripts/test.sh` (결과 `logs/coverage/`), 하네스 단위 테스트는
`./scripts/run_integration.sh --unit-only --coverage` 다.
