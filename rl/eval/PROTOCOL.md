# 보너스 1 평가 프로토콜 — 학습 정책 대 DWA (사전 등록)

> 이 문서는 **실행 전에** 커밋한다. 결과를 본 뒤에 이 문서의 기준·표본·순서를 바꾸지 않는다. 바꿔야 하면
> 새 데이터를 만들기 **전에** 개정 커밋을 하고 §12 개정 이력에 적는다. 판정 코드는 `amr_rl_eval/report.py`
> (`PREREG` 사전)이고, 이 문서의 값과 코드의 값이 다르면 시험(`tests/test_protocol.py`)이 깨진다.

## 0. 무엇을 보이려는가

명세 5장 보너스 1 (`31_*.md` 323–327행) 중 이 문서가 다루는 것은 325행 하나다.

> 325: 학습된 정책과 기존 DWA의 성능을 정량적으로 비교한다.

명세는 비교 방법·지표·합격선을 정하지 않는다. 그래서 아래의 기준은 **전부 우리가 정한 것**이고 명세 요건이
아니다 (handover1006 §7.2 의 교훈: 명세에 없는 기준을 "명세 미달" 로 적지 않는다). 명세 4장 지표(189–191행
동적 장애물, 157행 CTE)는 비교군마다 **점검 항목**으로 함께 보고한다 (§6.11).

추정 대상(estimand)은 두 가지를 섞지 않는다 (이론편 「학습 비교군의 정밀도는 시드 수가 정한다」).

## 1. 비교군

계약(`rl/contract/contract.md` §1, `feature/rl-contract`)의 정의를 그대로 쓴다. 모든 비교군은 같은 A\* 전역 경로,
같은 하류 사슬(정책 → velocity_profiler → safety_node → DiffDrive), 같은 속도 상한 아래에서 돈다.

| `arm` | 정의 | 이 문서에서의 역할 |
| --- | --- | --- |
| `A_dwa` | 팀 DWA 현행 그대로 (파라미터 동결 — 비교에 쓰는 커밋을 `commit` 열에 남긴다) | 기준 |
| `C_hybrid` | DWA 가행 후보 중 PPO 가 고르는 하이브리드 (하드 마스크 + 폴백) | **주 비교군 (확증)** |
| `B_ppo`, `B_sac` | 순수 RL (연속 가속도) | 보조 (탐색적) |
| `D_param` | DWA 파라미터 정책 (선택) | 보조 (탐색적) |

`safety_node` 는 확증 분석에서 항상 `on` 이다. `off`·`monitor`(개입 없이 개입했을 양만 기록)는 2D·Isaac
에서만 돌리고 따로 보고한다 — 정책 고유의 안전성과 시스템 안전성을 가르기 위함이다 (실무편 「0/240 …」 절).

## 2. 사전 등록 절차

1. 이 문서와 `report.PREREG` 를 커밋한 뒤에 평가 실행을 시작한다. 결과 CSV 의 `commit` 열에 평가 대상 커밋을 쓴다.
2. **체크포인트는 2D 검증 세트로만 고른다.** Gazebo 시험 시드는 선택에 쓰지 않는다 (winner's curse).
   주 체크포인트(`policy_id`) 는 Gazebo 확증 실행 전에 REPORT 나 이 문서 §12 에 적는다.
3. 순차 감시(§6.2)의 경계·상한은 실행 전에 고정한다. 조기 종료 규칙을 실행 중에 바꾸지 않는다.
4. Gazebo 시나리오 시드는 미리 뽑아 두고, 각 시드는 한 번만 쓴다. 실행 순서를 무작위로 섞고 그 순서를
   `exec_index` 로 남긴다. A 와 C 는 같은 시드 순서로 돈다 (짝).
5. 실패한 실행을 골라 다시 돌리지 않는다. 하네스·시뮬레이터 고장은 `outcome=error` 로 남기고(§6.6), 재실행은
   새 `exec_index` 로 **덧붙인다** (원래 행을 지우지 않는다).

열 정의에서 판정에 걸리는 것:

- **짝 키**는 (`scenario_set`, `scenario_id`, `scenario_seed`, `episode`) 이고 비교군·정책은 보지 않는다. 기준
  비교군 `A_dwa` 안에서는 (`simulator`, `safety_node`) 마다 이 키가 **하나**여야 한다 — A 를 여러 커밋으로 나눠
  돌렸으면 `episode` 를 커밋을 넘어 이어서 매긴다. 겹치면 `read_csv`·`report.load`·`report.pair_rows` 가
  오류를 낸다 (어느 기준 행과 짝지을지 조용히 고르지 않는다). DWA 파라미터 변형처럼 같은 키를 다시 도는
  기준 쪽 정책은 `A_dwa` 로 내지 않는다. 시험 비교군은 정책(학습 시드)마다 같은 키를 써도 된다.
- `outcome` 은 계약 §8 의 종료와 같다 — `success` = 목표 xy ≤ 0.10 m 이고 |v| ≤ 0.05 m/s, 같은 스텝에 접촉이면
  `collision`. `timeout` = 시간 상한 min(120, 20 + 3·L) s, `stall` = 20 s 동안 0.3 m 미만 이동. 성공률 분석에서
  `timeout`·`stall`·`error` 는 모두 실패다.
- `contacts` 는 **지면 진실 기하** 접촉이다 (Gazebo `collision_monitor`, 2D·Isaac 은 풋프린트 대 장애물). 센서 판정이
  아니다. 접촉은 즉시 종료여야 한다 (벽을 따라 미끄러지는 궤적이 남으면 SRCC 가 무너진다 — 계약 §8).
- `max_dev_m`·`return_max_s` 는 **활성 계획** 기준이다 (`tests/integration/amr_itest/metrics.py` 의 이탈 상태기계,
  0.30 m 진입·0.15 m 복귀). 계약의 학습 비용은 에피소드 동안 고정한 A\* 경로 기준이라 Gazebo 의 "첫 계획 기준" 에
  해당한다 — 둘 다 보고한다 (§6.11).
- `interventions`: safety node 출력이 입력과 다른 (|Δv| > 0.01 m/s 또는 |Δω| > 0.01 rad/s) 연속 구간 하나를 1 회로
  센다. `intervention_time_s` 는 그 구간 길이의 합. Gazebo 에서는 `cmd_vel_smoothed`(입력)와 `cmd_vel`(출력)을 같은
  시각으로 맞춰 계산한다 — 기존 하네스는 이 둘을 구독하지만 시행별로 저장하지 않는다 (§9).
- `jerk_lin_rms`·`jerk_ang_rms`: safety node 출력 명령(실제 적용된 명령)의 2 차 차분 / dt² 의 RMS.

## 6. 분석 계획 (사전 등록)

### 6.1 확증 대상

`C_hybrid` 의 주 체크포인트 하나 대 `A_dwa`, `gz_new600`, `safety_node = on`. 오류(`outcome = error`) 에피소드는
§6.6 규칙 하나로 다룬다 — 성공률 가설(H2·H3)에서는 C 의 오류를 **실패**로 세고 A 의 오류 짝은 빼며, 접촉(H1·H5·경보)과
복귀(H4)에서는 오류를 뺀다.

### 6.2 H1 — 접촉률 비열등성 (순차 감시)

`exec_index` 순서로 C 의 에피소드를 하나씩 본다. 무접촉이면 Λ += ln(0.995/0.98) = +0.01519, 접촉이면
Λ += ln(0.25) = −1.386. **Λ ≥ ln 40 = 3.689 이면 "δ = 2 %p NI" 를 선언하고 감시를 끝낸다.** 0 접촉이면 243 번째에서
끝나고 접촉 1 회마다 약 92 회 늘어난다. 600 회에 닿아도 선언하지 못하면 **미달** ("NI 미입증").

- Ville 경계라서 매 에피소드 들여다봐도 1 종 오류 ≤ α 다 (p ≥ p0 에서 우도비가 supermartingale). 모의
  4 만 회: 참 접촉률 0.25 % → 선언 0.966, 0.5 % → 0.779, 2 % → 0.020 (`tests/test_sequential.py`).
- H0 를 "p_C ≥ 2 %" (절대값)로 둔다. 새 시드 묶음에서 DWA 에 접촉이 나오면 실제 NI 귀무(p_C ≥ p_A + 2 %p)보다
  **어려운** 주장을 검정하는 셈이라 보수적이다.
- 에피소드 독립을 가정한다. `gz_new600` 은 시드마다 시나리오가 달라 이 가정에 가깝다.
- **확증 대체안 (사전 등록)**: `gz_new600` 생성기가 다음 물결 안에 준비되지 않으면 같은 규칙을 `gz_s08_actor42`
  (C 8 실행 × 30, 상한 600 = 20 실행) 에 적용한다. 이때 결론은 "seed 42 actor 구성에서, 시행이 독립이라면" 으로
  **한정**해 적고, 같은 실행 안의 시행이 직렬로 의존한다는 점을 함께 적는다. 판정표는
  `scripts/evaluate.py --fallback-set` 으로 만든다 (`report.PREREG['confirm_set_fallback']`). 짝은 C 의 k 번째
  실행 ↔ 기준선의 k 번째 실행 (`episode` = k, §3.1) 이다.

### 6.3 H2–H5 — 고정 순서

H1 이 충족일 때만 H2 를 보고, 앞 가설이 충족일 때만 다음으로 간다. 각 가설을 α = 0.025 그대로 검정해도 가족 오류율이
α 이하다. 멈춘 뒤의 가설은 **검정 안 함** 으로 적고 값은 참고로만 싣는다.

| 순서 | 가설 | 자료 | 검정 | 충족 조건 |
| --- | --- | --- | --- | --- |
| H2 | 성공률 비열등 (δ_s = 3 %p) | 같은 시드 짝 (A·C). C 오류 = 실패, A 오류 짝은 뺀다 (§6.6) | Tango score (실패 지시변수, 짝) | z < −1.96 |
| H3 | 성공률 우월 | H2 와 같은 짝 | McNemar mid-p 단측 | p ≤ 0.025 |
| H4 | 복귀 시간 우월 | 둘 다 오류가 아닌 짝의 `return_max_s` | Wilcoxon 부호순위 단측 (차 = C − A) + Hodges–Lehmann 구간 | p ≤ 0.025 |
| H5 | 접촉률 NI δ = 1 %p (보조) | C 전체 대 A 전체 (비짝) | Farrington–Manning score **와** Newcombe hybrid 상한 | 둘 다 통과 |

H5 는 0 접촉이어도 C 가 381 회 이상이어야 닿는다 (닫힌 해 n > z²(1 − δ)/δ). C 가 300 회에서 멈추면 H5 는 미달이다.

### 6.4 보조 비교군 (B_ppo·B_sac·D_param) — 탐색적

같은 SPRT 를 돌려 상태를 적고, FM NI(δ = 2 %p) p 값을 Holm 으로 보정해 싣는다. **확증 주장에 쓰지 않는다.**
Holm 으로 넷을 모두 확증하려면 0 접촉 기준 비교군당 306 회가 필요하다 — 예산 밖이라 고르지 않았다.

### 6.5 안전 경보 (감시 규칙, 확증 아님)

C 의 누적 접촉이 같은 시드 DWA 대비 **Barnard 정확 비조건부 단측 p < 0.05** (합동 분산 score 통계량, 귀무 모수 격자
200 점) 가 되면 C 의 Gazebo 평가를 멈추고 실패 모드 분석으로 돌린다 (`report.safety_alarm`). 240 대 240 에서 DWA 가
0 접촉이면 **0 대 3** (p = 0.0481) 이 첫 문턱이다. 비교: Boschloo 는 0 대 5 (p = 0.0254, 0 대 4 는 p = 0.0550),
Fisher 도 0 대 5. 이론편은 Boschloo 를 권했지만 그 근거("Boschloo 는 0 대 4 부터, Barnard 는 덜 강력")가 표 방향
오류에서 나왔다 (§10). 반복 확인에 대한 α 보정을 하지 않는 안전 규칙이다 — 확증 결론에 쓰지 않는다.

### 6.6 오류·재실행

- `outcome = error` 는 성공률에서 **실패**로 센다 (보수적). 적용되는 곳: 비교군 요약·시드 집계(§6.8)의 성공률, 확증
  H2·H3, 2D 게이트(§6.7)의 성공률 NI. 짝지은 비교에서 **기준 A 쪽 오류**는 실패로 세지 않고 그 짝을 뺀다 — A 의
  오류를 실패로 세면 C 에 유리해져 보수적이지 않다.
- 접촉률(H1·H5·안전 경보·게이트 접촉 상한)과 복귀 시간(H4)의 분모에서는 뺀다 (관측이 없다). 오류 수와 뺀 짝 수를
  판정표에 따로 적는다.
- 예 (`tests/test_report.py::test_c_errors_count_as_failures_in_h2`): 306 짝에서 C 오류 6 (1.96 %, 문턱 안),
  C 만 실패 3, A 만 실패 0 이면 H2 의 z = −0.060 (미달) 이다. 오류를 짝에서 빼면 z = −2.031 로 충족이 되어 버린다.
- 비교군 하나의 오류율이 2 % 를 넘으면 그 비교군의 확증은 **판정 불가** — 하네스부터 고친다.
- 재실행은 덧붙이기만 한다 (§2-5). 오류 행의 원인은 `run_tag` 의 로그로 남긴다.

### 6.7 2D → Gazebo 진출 게이트

체크포인트마다: (1) `sim2d_collision1e5` 의 접촉 CP 95 % 상한 ≤ 0.5 % (오류 제외), (2) `sim2d_heldout` 에서 2D-DWA
대비 성공률 NI δ = 2 %p (Tango 짝, α = 0.025, 체크포인트의 오류 = 실패, DWA 오류 짝은 뺀다 — §6.6). 둘 다 충족한
체크포인트만 Gazebo 로 보낸다. 주 체크포인트는 게이트를 통과한 것
중 `sim2d_heldout` IQM 이 가장 높은 것으로 **미리** 정한다 (동점이면 시드 번호가 작은 것).

### 6.8 시드 집계 (2D·Isaac, 알고리즘 수준 — 기술 보고)

- 점수 행렬: run = 학습 시드, task = `difficulty` 층, 칸 = 그 시드·층의 성공률. DWA 는 run 1 개.
- IQM (25 % 절사 평균) + 층화 부트스트랩 95 % 백분위 구간 (2 000 회, 층 안에서 시드를 복원 추출, rliable 정의).
- 개선 확률 P(X > DWA) (층별 Mann–Whitney 평균) 를 IQM 차와 함께 싣는다.
- 시드별 원표를 함께 낸다. 시드가 5 개 미만이면 **판정 불가** 표시.
- Gazebo 는 체크포인트 하나만 보므로 시드 집계를 하지 않는다.

### 6.9 최악 난도 CVaR (2D)

레벨 = `scenario_id`. α = 5·10·25 % 에서 최악 ⌊αL⌋ 레벨의 평균 성공률을 plug-in(비관 편향)과 cross-fit(낙관 편향,
반씩 나눠 고르고 평가, 두 방향 평균) 둘 다 싣는다. 레벨당 최소 에피소드가 50 미만이면 **판정 불가** 표시.
연속 손실(최소 이격 부족분 등)의 꼬리는 Rockafellar–Uryasev 표본식(`cvar.cvar_loss`)으로 싣는다.

### 6.10 시뮬레이터 간 순위 상관 (SRCC)

공통 `scenario_id` 에서 정책별 성공률로 Spearman ρ·Kendall τ, Bonett–Wright 95 % 구간, 시나리오 수준 부트스트랩 95 %
구간, 단측 순열 p 를 낸다. 판정 (`report.srcc_verdict`):

- 정책 N < 10 → **판정 불가**.
- N ≥ 10 이고 **Bonett–Wright 95 % 하한과 시나리오 부트스트랩 95 % 하한이 모두 0.5 초과** → **충족**. 이론편 계획 표의
  "SRCC CI 하한 > 0.5" 를 두 구간 모두에 건다 (BW 는 정책 수, 부트스트랩은 시나리오 표집의 불확실성을 본다).
- 그 밖 (하나라도 0.5 이하, 순위가 뒤집힌 경우 포함) → **미달**.

충족이어도 Gazebo 확증(§6.2)을 대신하지 않는다 — "2D 순위가 이 쌍에서 옮겨진다" 는 근거일 뿐이다. 같은 비교군의
시드들은 독립 정책이 아니므로 구간이 낙관적이고, 충족도 그만큼 낙관적이라고 적는다.
