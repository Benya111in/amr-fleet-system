## 1. 비교군

모든 비교군은 **같은 A\* 전역 경로**(N:25-49 `amr_navigation::AStarPlanner`), **같은 하류 사슬**
(정책 → `velocity_profiler`(V) → `safety_node` → DiffDrive), **같은 운용 속도 상한 `v_cap` = 1.0 m/s**
(N:104 DWA `max_vel_x`) 아래에서 비교한다 (「실무」 17행 "같은 safety node 아래에서 짝지어 비교").

| 비교군 | 정의 | 행동 | 학습 |
|---|---|---|---|
| **A** | 튜닝된 자체 DWA (`amr_navigation::DWAController`, N:100-359) — 현행 그대로 | (v, ω) 명령 | 없음 (기준선) |
| **B** | 순수 RL: 관측 → 연속 가속도 (a_v, a_ω) | §5.1, 2 차원 연속 | PPO(주력), SAC(둘째) — 같은 관측·보상·시드 |
| **C** | 하이브리드: DWA 의 가행성·VO 판정을 통과한 **상대 가속도 격자 셀** 중 PPO 가 하나 선택, **하드 마스크**, **항상 가용한 폴백** | §5.2, 100 범주 (99 셀 + 폴백) | BC(DWA 시연, categorical CE) → masked PPO |
| **D** (선택) | DWA 파라미터 정책 (SMDP) | §5.3, 1–2 Hz 로 DWA 가중치·속도 상한 | PPO (SMDP 할인) |

근거: 「실무」 15–27행(비교군 표, C 주력, residual 제외 26행), 「이론」 47–56행(DWA = 온도 0 샘플링 MPC),
65–92행(마스크 정당화·명제 A/B), 113–118행(D = SMDP). 하이브리드에 이산 SAC 를 쓰지 않는 이유: 마스크된 정책의
최대 엔트로피가 상태마다 log|A_valid(s)| 로 달라 고정 목표 엔트로피가 협로에서 달성 불가 (「이론」 149–153행).

**DWA 후보 집합을 C++ 에서 꺼내는 방법 (r3 용)**: `core::DwaPlanner::compute()` 의 결과 `DwaResult` 는
선택된 `best` 하나와 집계만 담고 **후보 목록(`cands`)을 밖으로 내지 않는다** (`dwa.hpp:303-321`, `dwa.cpp:675`).
공개 단계 함수 `windowCenter`·`dynamicWindow`·`sampleVelocities`·`simTime`·`rollout`(`dwa.hpp:341-374`)과
`velocity_obstacle.hpp` 의 `chordVelocity`·`velocityObstacleTime` 은 공개라 조합할 수 있다. 그러나 DWA 자체의
표본은 창 폭에 맞춘 `linspace(11×31)` + ω=0 열 추가 + 제동 후보라서 **셀 수와 의미가 상태마다 바뀐다**
(`dwa.cpp:137-172`). 그래서 C 는 DWA 의 표본 대신 §5.2 의 고정 격자를 쓰고, DWA 의 **판정 규칙**(롤아웃
충돌·VO·포화)만 같은 상수로 재현한다. 장애물 표현은 코스트맵이 아니라 **같은 주기의 LiDAR 끝점**(§5.2) —
세 환경이 똑같이 구현할 수 있는 유일한 입력이기 때문이다 [설계 선택]. DWA 의 양보·게이트·탈출 계층
(`dwa.cpp:480-660`)은 마스크에 넣지 않는다 (그 계층은 비용·결정이고 C 에서는 정책이 대신한다).

정의와 근거:

- **LiDAR**: 여유거리 = 빔 끝점(로봇 좌표, 원점 (0.15, 0))에서 풋프린트 사각형까지 거리, 안쪽이면 0.
  무효 빔(null/NaN/inf, r < 0.10, r > 25)은 무반사(10 m). 720 → 90–120 단순 다운샘플은 좁은 동적
  장애물을 놓친다는 보고가 있어(「실무」 30행, arXiv 2501.02902) **섹터 최솟값 풀링**(FlashNav 방식, 같은 행)을
  쓴다. 섹터 폭 2° 는 5 m 에서 17 cm 다 [설계 선택: 180 섹터]. 1D-CNN 은 정책 구조의 선택(r1·r2)이다.
- **실행값과 명령값을 모두**: v_meas·a_meas(프로파일러 상태 = 실행 가속도)는 Markov 성 유지에 필요하고(「이론」 117행),
  최근 2–3 행동(명령)·스캔 나이·트랙 나이는 지연 MDP 를 Markov 로 되돌리는 관측 증강이다(「이론」 297–299행).
  "최근 행동" = **클램프·폴백 뒤 실제로 보낸 명령 가속도** (B 의 원출력 u 가 아니다). 전이 뒤
  prev_actions = [a_t, a_{t−1}, a_{t−2}] 로 민다 (에피소드 시작은 0).
- **이탈 블록은 갱신 뒤 값**: s' 의 관측에는 `reward.step()` 이 돌려준 이탈 상태(`StepResult.dev`)를 넣는다.
- **A\* subgoal**: 경로의 다음 0.5 m 간격 5 점 — 최종 목표 대신 넣었을 때 성공률 90.2 → 98.9 %(「실무」 30행,
  arXiv 2605.02528). 실무 보고서의 "단위벡터" 대신 **극좌표(거리, sin, cos)** 를 써서 경로 이탈 시 거리 정보도 준다.
  e_y·e_ψ 는 CTE 수준 추종에 필요한 경로 상대 오차다(「이론」 61행). 투영 = **전역 최근접점, 동률이면 작은 호길이**
  (`geometry.project_onto_path`). 경로는 에피소드 동안 고정이다(§8).
- **트랙**: DWA 플러그인과 같은 선별·외삽(`dwa_controller.cpp:339-349`), 로봇 중심 거리 ≤ 10 m, (거리, id) 오름차순
  상위 8. 속도는 **지도 기준 속도를 로봇 축으로 회전**한 것(로봇 속도를 빼지 않는다). TTC 는 추적기의 TTC 필드를
  쓰지 않고 **계약 함수로 다시 계산**한다: 로봇이 전방 직진 v_meas, 장애물 등속, 원 반경 0.361 + 0.30 의 첫 접촉
  시각(`velocityObstacleTime` 과 같은 식, 지평 5 s, P:210) — 세 환경에서 의미가 같아야 하기 때문이다
  [설계 선택]. 클래스·크기는 `TrackedObstacle.msg` 에 없어서 넣지 않는다(보고서와 다름, §13).
- **안전 상태**: 필터가 래치·존 상태를 가지면 그것을 관측해야 같은 관측에서 다른 전이가 생기지 않는다
  (「이론」 257행 "관측에 현재 존, 적용 중인 속도 상한, 근접 정지 여부, 최소 TTC를 넣는다").
- **이탈 상태**: 복귀 5 s 요구는 현재 상태만으로 정의되지 않으므로 모드·타이머로 상태를 증강한다
  (「이론」 217행, reward machine).
- **기억**: 에피소드 상수 맥락(적재·지연)은 프레임 스택으로 식별되지 않으므로 GRU 를 권장한다(「이론」 277행,
  「실무」 30행 GRU 82 % vs MLP 67 %). 은닉 상태는 관측이 아니라 ONNX 입출력이다(onnx_io.md).

## 5. 행동과 적분

공통: 정책은 **가속도**를 낸다 — 1차(속도) 행동으로 학습한 정책은 가속도 제약 아래 성공률 0.99 → 0.52
(「실무」 34행, KinematicRL), 가속도 좌표에서 동적 창은 상태 무관 상자다(「이론」 117행).
명령 적분: v_cmd' = v_cmd + a_v·Δt, ω_cmd' = ω_cmd + a_ω·Δt (Δt = 0.1). 버퍼에는 **정책이 낸 원출력과 그
log-prob** 를 저장하고, safety node 가 바꾼 행동을 정책 행동으로 기록하지 않는다(「이론」 125행).

### 5.1 비교군 B (연속)

- 정책 출력 u ∈ [−1, 1]² (tanh 뒤). (a_v, a_ω) = (u₀·1.0, u₁·2.0) (R:59, R:61).
- 속도 한계는 **ray 클램프**: v' = clip(v_cmd + a_v·Δt, 0, min(v_cap, 2.0)), ω' = clip(ω_cmd + a_ω·Δt, ±1.5)
  (「이론」 117행 — 클램프는 score function 을 바꾸지 않는다, Stolz Prop.1). 실행 가속도 = (v' − v_cmd)/Δt.
- 저크는 정책 단계에서 묶지 않는다. 하류 프로파일러가 묶고(§5.4), 그 상태가 관측에 있다.
- 기준 구현 `kinematics.integrate_b`, golden `i01_action_integration`.

### 5.2 비교군 C (후보 선택, 하드 마스크)

- **격자**: a_v ∈ {−1.0, −0.8, …, 1.0} (11, 간격 0.2 = 저크 2.0 × 0.1), a_ω ∈ {−2.0, −1.5, …, 2.0}
  (9, 간격 0.5 ≤ 각저크 6.0 × 0.1). 인덱스 i = i_v·9 + i_ω (0…98). **폴백 = 99**. 직전 명령 기준
  **상대 가속도 격자**라서 행동 집합이 고정되고 가용성만 상태에 따라 바뀐다(「이론」 69행, stochastic action set).
- **셀 유효 조건** (모두 만족): (1) 속도: 0 ≤ v' ≤ min(v_cap, 2.0), |ω'| ≤ 1.5; (2) 저크: |a_v − a_v,prev| ≤ 0.2,
  |a_ω − a_ω,prev| ≤ 0.6 (「이론」 91행 "jerk 제약은 … mask 단계에 넣는다"); (3) 가행성: (v', ω') 등속 원호를
  k·0.1 s (k = 1…⌈T_sim/0.1⌉) 자세마다 풋프린트에 **이번 스캔의 유효 끝점**이 없다 (경계 포함 = 충돌, 팽창 0
  [설계 선택: DWA 치명 셀 외곽선 판정과 같게]), 호길이 |v'|·k·0.1 > d_goal + 0.1 인 자세부터는 검사하지 않는다
  (d_goal = max(남은 호길이, 목표 직선거리), `dwa.cpp:449-459`). n = ⌈T_sim/0.1⌉ 개 자세 **전부**를 **모든** 유효
  끝점으로 검사한다 (`dwa.cpp:175-187`·`:711-723` 과 같은 n). 거리 사전필터를 두려면 반경은 |v'|·n·0.1 + 0.361
  이상이어야 한다 — |v'| > 1.0 이면 T_sim 이 0.1 의 배수가 아니어서 |v'|·T_sim 은 마지막 자세에 못 미친다
  (v1.0.0 기준 구현의 결함, golden `d15`); (4) VO: 동적 트랙(§4 선별 ∩ 속력 ≥ 0.2 ∩ 거리 ≤ 6 m)
  마다 v_eff = chordVelocity(0, v', ω', 2.0), 반경 0.361 + 0.30 + 0.3 의 VO 진입 시각이 없다.
- **VO 포화**: (1)–(3) 을 통과한 셀이 있는데 모두 VO 에 걸리면, VO 진입 시각 ≥ 최대 − 0.02 s 인 셀을 유효로 한다
  (DWA 선택 규칙 `dwa.cpp:946-` 과 같은 집합 — DWA 가 고를 수 있는 셀이 마스크 안에 남아야 BC 가 실현 가능).
- **폴백(99)**: DWA 제동 후보와 같은 규칙 v' = max(0, v_cmd − 0.1), ω' = ω_cmd − sign·min(|ω_cmd|, 0.2)
  (`dwa.cpp:163-170` 을 0.1 s 로). **항상 유효**하고 저크 조건에서 면제된다(가용 집합이 비지 않게, 「이론」 69행).
  폴백 선택 빈도는 별도 지표로 기록한다(같은 행).
- 마스크는 결정 시점 정보만의 함수이고(조건 1), rollout 때 마스크를 버퍼에 저장해 update 에서 **같은 마스크로**
  log-prob·엔트로피를 다시 계산한다(조건 2, 「이론」 67행). 마스크된 logit = −1e9 (onnx_io.md).
- 정책 관측(섹터 LiDAR)이 마스크 입력(전체 스캔)보다 거칠므로 정책·critic 이 **마스크를 입력으로 받는다**
  (조건 4, 「이론」 67행). 후보 특징(셀별 DWA 비용항) 입력은 v2 로 미룬다(§14).
- BC 레이블: DWA 가 낸 (v, ω) 를 가속도 ((v − v_cmd)/Δt, (ω − ω_cmd)/Δt) 로 바꿔 `kinematics.nearest_cell`
  (정규화 거리 최소, 동률은 작은 인덱스); 그 셀이 마스크 밖이면 폴백. BC 손실은 categorical cross-entropy
  (「이론」 109행).
- 배포 argmax 의 chattering 방지 히스테리시스(직전 셀 가산점, 「이론」 167행)는 플러그인 파라미터 (기본 0).
- 기준 구현 `mask.compute_mask`, golden `d01`–`d17`.

### 5.3 비교군 D (선택, SMDP)

- 행동: DWA 가중치 배수 (heading, clearance, velocity, path, dynamic) ∈ [0.5, 2.0] 와 max_vel_x ∈ [0.3, 1.0],
  k = 5–10 결정 주기(0.5–1 s)마다 결정. 제동 감속·VO 여유·TTC 임계·inflation 은 학습 대상에서 뺀다
  (「이론」 115행). 직전 파라미터를 관측에 덧붙이고 전환 벌점을 준다(같은 행).
- 갱신 목표 = Σ_{i<k} γ^i r_{t+i} + γ^k V(s_{t+k}) — γ 는 0.1 s 단위 그대로(§9). contextual bandit(γ_D = 0)을
  기준선으로 함께 둔다(같은 행). ONNX 계약은 v2 (§14).

### 5.4 하류 명령 사슬 (환경이 넣어야 하는 고정 구성요소)

정책 명령 (v_cmd, ω_cmd) → **velocity_profiler 기준 경로**(50 Hz, 선속도 `JerkLimitedFilter`(a 1.0, 저크 2.0),
ω 는 |v*| > 0.05 이면 곡률 보존 ω_ref = (ω*/v*)·v_ref 를 α 2.0 로 변화율 제한, 아니면 각저크 6.0 필터) →
**플랜트**(1차 지연 T_m + 순수 지연 T_d, DR §11) → safety φ(§7.4) → 실행 속도. 1.0 m/s² 제약과 저크 제한 프로파일러는
랜덤화 대상이 아니라 **고정 구성요소**다(「실무」 84행). 기준 구현 `profiler.ProfilerReference`(PI·재동기화 제외 —
플랜트가 기준 모델과 같으면 PI 가 개입하지 않는다, `velocity_profiler.hpp` 머리말), golden `p01_profiler_sequence`.

## 6. 보상

r_t = r_time + r_shape + r_smooth + r_track + r_goal + r_collision

| 항 | 식 | 값 | 근거 |
|---|---|---|---|
| 시간 | −c | c = 0.02 / 스텝 (= 0.2 /s) | 빨리 가라는 유인은 shaping 이 아니라 기저 보상의 시간 비용으로 (「이론」 181행) |
| 진행 (PBRS) | γ·Φ(s') − Φ(s), Φ(s) = −κ·d_arc(s), **종단에서 Φ(s') = 0** | κ = 1.0 /m | 「이론」 175–185행 (Ng 1999 의 세 조건: 같은 γ, 유계, 종단 0) |
| 평활 | −w·[(Δa_v/1.0)² + (Δa_ω/2.0)²] | w = 0.0125 (최대 0.1) | 행동 변화율 = 이산 jerk 비용, 직전 행동이 관측에 있어야 Markov (「이론」 229행) |
| 추종 | 이탈 구간 밖에서만 −q·min(e/0.05, 3)² | q = 0.004 (최대 0.036) | CTE 는 TRACK 모드에서만 (「이론」 217–223행), 회피 중에는 끈다 |
| 목표 | +G (성공 시) | G = 10 | [설계 선택] |
| 충돌 | −C (충돌 시) | C = 30 | §6.2 |

- **d_arc** = 경로 길이 − 로봇 투영 호길이 (A\* 경로 호장). 보고서의 Φ = κ·s_arc 와 상수 κ·L 만 다르다 — 상수 차이는
  PBRS 불변성을 깨지 않지만, Φ = −κ·d_arc 쪽이 shaped 가치 V − Φ 를 경로 길이 L 과 무관하게 만든다
  (「이론」 185행: PBRS = critic 을 V̂ ≈ Φ 로 초기화한 것) [설계 선택].
- **종단 Φ = 0 의 결과**: 충돌 스텝의 shaping 은 +κ·d_arc(s) (멀리서 충돌할수록 큰 양수)다. 이것은 오류가 아니다 —
  종단 궤적의 할인 shaping 합은 성공·충돌 모두 −Φ(s₀) 로 같고(「이론」 185행), golden `s03_collision`
  (r_shape = +8.0)이 이 값을 고정한다. 종단 Φ 를 위치로 계산하면 "멀리서 충돌할수록 큰 벌점"이 숨어 들어가
  최적 정책이 바뀐다 — 구현자가 가장 실수하기 쉬운 곳이다.
- **truncation**(시간 상한·정체)에서는 Φ(s') 를 그대로 쓰고 마지막 상태 가치로 bootstrap 한다(「이론」 131행).
- 보상 정규화는 **표준편차로 나누기만** 한다. 평균을 빼면 매 스텝 상수를 더한 것이 되어 생존·조기 종료 유인이
  바뀐다(「이론」 169행).

### 6.1 진행 보상 Δd 를 쓰지 않는 이유 (시험으로 확인)

κ(d − d') = [γΦ(s') − Φ(s)] − κ(1−γ)d' (비종단 스텝, Φ = −κd) — 두 번째 항은 어떤 퍼텐셜 차분으로도 쓸 수 없는
**거리 비례 생존비**다(「이론」 177–179행). 종단 스텝에서는 Δd 가 추가로 −γκd' 를 숨긴다. 그래서 Δd 는 최적
정책을 바꾼다. `tests/test_reward.py::test_pbrs_preserves_optimal_policy_but_delta_d_does_not` 가 이를 사슬 MDP
(30 m, 행동: 안전 전진 / 2 칸 돌진(0.2 % 충돌) / 정지, 이 계약의 c·G·C·γ)로 보인다 [계산]: 기저 보상과 PBRS 의 최적
정책은 모든 상태에서 같고(돌진 없음), Δd 는 목표에서 **16.8 m 넘게 먼 상태 133 개에서 충돌 위험이 있는 돌진**을
고른다 — 숨은 생존비가 먼 곳에서 서두르게 만든다. 항등식 자체는 `test_progress_reward_decomposition` 이 확인한다.

### 6.2 충돌 벌점 C 와 시간 비용 c 의 창 [계산]

- **자살 방지 (하한)**: 충돌이 남은 시간 비용을 끊는 이득은 최대 c̄ = c/(1−γ) = 4.0 이고 PBRS 는 이 비교에 기여하지
  않으므로 C > 4 가 필요하다(「이론」 201행). C = 30.
- **무할인 궤적 순서**: τ_crash ≺ τ_idle 이 무할인 기저 보상에서도 성립하려면 C > c × (시간 상한 스텝 수) =
  0.02 × 1200 = 24 → C = 30, 시간 상한 ≤ 120 s (§8). Knox 식 순서 시험 τ_crash ≺ τ_idle ≺ τ_succ, τ_loiter ≺ τ_succ 를
  할인(shaping 포함)·무할인(기저) 둘 다로 `test_trajectory_ordering_knox` 가 확인한다(「이론」 213행).
- **정지 유인 (상한)**: 조우 τ = 2 s 뒤 확률 p 로 충돌, 아니면 T = 30 s 뒤 도착 vs 영구 정지의 무차별 위험도
  p\* = γ^T(G + c̄)/(γ^T(G + c̄) + γ^τ(C − c̄)) (「이론」 189–199행). 이 계약 값(G 10, C 30, c 0.02)에서
  γ = 0.995 → **p\* = 11.7 %**, γ = 0.99 였다면 2.5 % [계산]. 충돌의 나머지 억제는 제약(§7)이 맡는다 —
  창이 좁으면 페널티가 아니라 제약으로 옮기라는 처방(「이론」 201행)을 따른 것이다.

## 7. 비용과 제약

비용은 스텝마다 5 채널, **제약에는 비할인 에피소드 합**을 쓴다 — 할인 비용 J_C 로는 Pr[개입 ≥ 1] ≤ J_C/γ^T 밖에
말할 수 없고(10 Hz·60 s·γ 0.995 에서 γ^−T ≈ 20 [계산]), 비할인 기대 개입 수는 Markov 부등식으로 확률 제약을
함의한다(「이론」 241행). 비용 critic 학습에 할인을 쓰는 것은 별개다.

| # | 이름 | 스텝 비용 | 기본 예산 d (에피소드 합) |
|---|---|---|---|
| 0 | `collision` | 접촉 1 (지면 진실 기하, 센서 섹터가 아니다 — 「이론」 213행) | 0.02 |
| 1 | `intervention` | safety 틱들의 평균 ((v_in − v_out)/1.0)² + ((ω_in − ω_out)/1.5)² | 미정 → DWA 실측 × 1.2 (§7.2) |
| 2 | `deviation_1m` | 1[e > 1.0 m] | 5 (= 0.5 s) |
| 3 | `return_5s` | 1[이탈 구간 중 & 최대 이탈 뒤 > 5 s] | 10 (= 1 s) |
| 4 | `cte_track` | 1[이탈 구간 밖 & e > 0.10 m] | 50 (= 5 s) |

e = 경로 최근접점까지 거리 (부호 없음). 이탈 구간 = metrics.py 와 같은 상태기계(§2 마지막 행), 시험
`test_dev_machine_matches_integration_metrics` 가 무작위 40 열에서 구간·최대·끝 시각이 일치함을 확인한다.

### 7.1 개입 비용은 "보정 크기"다

개입 **이벤트**를 비용으로 두고 d = 0 으로 잡으면 Slater 조건(제약을 엄격히 만족하는 정책 존재)이 깨지고 λ 가
발산한다; 정지한 로봇에 사람이 걸어와도 개입이 생기므로 정지 정책조차 비용이 0 이 아니다(「이론」 235–237행).
**보정 크기 ‖u − φ(u)‖²** 는 정책이 이미 정지를 명령한 상태의 개입을 0 으로 만든다(같은 행). 존 진입을 비용으로
쓰지 않는다(0.60 m 통로 통과까지 벌하게 된다, 같은 행). u = safety node 입력(프로파일러 출력), φ(u) = 출력.

### 7.2 예산과 Slater

- 모든 d > 0 (Slater). 충돌 0.02 /에피소드: 현 DWA 의 0/240 은 시행당 접촉률 95 % 상한 1.24 % 라는 뜻뿐이고
  (「실무」 3행), d 는 그보다 커야 DWA 가 Slater 증인이 된다 [설계 선택].
- `intervention` 의 d 는 **미측정**이다. r2 가 2D 에서 DWA(비교군 A)를 같은 φ 로 돌려 에피소드 평균을 재고 그 ×1.2 로
  정한다(「이론」 237행 "d를 현재 DWA가 실제로 달성하는 개입률보다 약간 크게"). 그 전까지는 {0.02, 0.05, 0.1, 0.2}
  를 훑어 (개입, 주행시간, 성공률) Pareto 곡선과 무릎점을 보고한다(「이론」 247행). 마지막 λ 값을 함께 보고한다.
- 승수 갱신은 PID Lagrangian 을 권장한다(진동·overshoot 완화, 「이론」 249행).
- 이탈·복귀·CTE 예산(2–4)은 [설계 선택] 이며 DWA 실측 분포(시나리오 08)를 r4 가 재서 고친다.

### 7.3 안전 필터는 환경(전이)의 일부

학습 중 φ 를 켠다 — 필터는 배포에도 남으므로 "이 필터 아래 최적"이 우리에게 의미 있는 최적이다(「이론」 255행).
정책 버퍼에는 원출력을 저장하고(§5), 개입은 비용 1 번으로 처벌한다(「이론」 259행 2×2 설계와 monitor-only 평가는 r4).

### 7.4 φ 의 정본과 safety_lite

정본 φ = C++ `amr_perception::SafetyGate` (`safety_gate.cpp`). 2D 는 그것을 바인딩해 같은 코드를 쓰는 것을 권장한다
(「이론」 257행 "safety node의 판정 로직을 2D 시뮬레이터에 바인딩해 같은 코드를 쓴다"). 바인딩이 없을 때의 최소 규칙이
`safety.safety_filter` (safety_lite, golden `f01_safety_lite`):

- 들어가는 것: 존 상한(점 속도 0.5/0.2), 여유거리 상한, TTC 상한, 곡률 보존 스케일, STOP 래치 = 0, 확정 전 STOP 은
  CRITICAL 로 (`safety_gate.cpp:808-812`).
- **빠진 것** (정본과 다르다): 스윕 풋프린트 접근 거리 D 의 계산(입력으로 받는다), STOP 확정 2 프레임·히스테리시스,

  적는다.

## 8. 종료·에피소드 경계

| 사건 | 판정 | 처리 |

  일정 비율 균일 DR (「실무」 99행, 「이론」 295행). 적재·지연·누락률 같은 aleatoric 파라미터를 커리큘럼이 고르지 않는다(CICS, 같은 행).

## 12. 구현 일치 규칙 (r1·r2·r3)

- golden 사례 31 개: `decision` 17 (관측 291 + 마스크 100 + 셀별 판정 + VO 시각 + 폴백), `step` 11 (보상 항·합,
  비용 5, 이탈 상태, 종단), `integrate` 1, `profiler` 1, `safety` 1. 입력 상태 스키마 = `state.py` `State`.
- **좌표 변환과 VO 분기를 덮는 사례**: 트랙 속도의 지도→로봇 축 회전은 관측(227–290)과 VO 마스크에 함께 걸리므로
  θ ≠ 0 인 자세에 vx·vy 가 모두 0 이 아닌 트랙을 둔 `d16`(θ 1.2, 트랙 5 개, VO 진입 시각이 셀 사이에서 τ 를
  가로지름)·`d17`(θ −2.3, VO 원뿔 접선이 셀 사이를 지남)이 있다. 둘 다 **비포화**이고 9 셀 중 일부만 VO 로 거부된다
  (§5.2 (4) 의 일반 분기). `d06` 은 VO 음성 사례(최근접 거리 > 합성 반경), `d07`·`d11` 은 포화 사례다.
  속도를 회전하지 않거나 반대로 회전하는 구현, VO 에만 지도 속도를 쓰는 구현은 `d16`·`d17` 에서 어긋난다
  [측정: 변이 시험 2026-10-06, `logs/agents/r0-contract/mutation_review.log`].
- JSON 에는 inf/NaN 이 없다: 무반사 빔·상한 없음·TTC 없음·VO 없음 = `null`.
- 허용오차(`tolerance` 블록): 관측 1e-5, VO 시각 1e-4, 보상 1e-4, 비용 1e-6, 프로파일러 1e-6, 마스크·불리언 정확 일치.
  생성기가 경계 민감 사례(풋프린트 침투·목표 너머·포화 동률, VO 의 모든 분기(반경 안팎·접근 부호·접선·τ)를 유한·무한
  양쪽에서, 트랙 선별 속력 문턱·거리 문턱·거리 순서·관측 TTC 분기가 1e-4 안)를 거부하므로 float32 구현도 마스크와
  트랙 순서가 정확히 같아야 한다.
- float32 구현의 주의: Φ = −κ·d_arc 는 30 m 경로에서 3.6e-6 정밀도라 γΦ' − Φ 에서 상쇄 오차가 난다 — **d_arc 와
  shaping 은 float64 로** 계산한다.
- 좌표: 지도 좌표 자세 (x, y, θ), wrap(a) = a − 2π·floor((a + π)/2π) ∈ [−π, π).
- **C++ 원본과의 대조**: `tools/crosscheck_cpp.sh` 가 ROS 비의존 코어(`dwa.cpp`·`velocity_obstacle.cpp`·
  `velocity_profiler.cpp`·`safety_gate.cpp`)를 직접 빌드해, 이 기준 구현이 이식한 함수(VO 시각·chord 속도·T_sim·원호
  롤아웃·제동 후보(=폴백)·프로파일러 기준·여유거리 상한·꼭짓점 속력·존)와 결정적 난수 3 900 건에서 1e-9 안에서 같은지
  본다. 롤아웃 표본은 v ∈ [0, 2.0] (T_sim 1.5–2.5 s 전부)이고, C++ `integrateArc` 는 θ 를 [−π, π) 로 감으므로
  (`geometry.cpp:191`) 각은 감은 차이로 비교한다 [측정: 2026-10-06, 불일치 0,
  `logs/agents/r0-contract/crosscheck_cpp_review.log`]. 원본을 바꾸면 이 도구를 다시 돌린다.

## 14. 미해결·위험 (다음 물결)

1. **개입 예산 d₁ 미측정** — DWA 의 2D 개입 크기 분포가 필요하다 (r2·r4).
2. **C 의 후보 특징** (셀별 DWA 비용항 8 개, 「이론」 93–101행 KL 정규화 해석)은 v2. 지금은 마스크만 입력이다.
3. **마스크의 장애물 입력이 LiDAR 끝점**이라 DWA(코스트맵, 정적 지도 포함)와 같지 않다. 가림 뒤 정적 구조물은
   DWA 만 본다. 2.5 s·≤ 2.9 m 지평에서는 영향이 작다고 보지만 **미측정**이다.
4. **safety_lite 는 정본이 아니다** (§7.4). Isaac 이 lite 를 쓰면 2D(바인딩)와 φ 가 다르다.
5. **전역 투영**은 경로가 자기 자신에 1 m 안으로 다가오는 U 턴에서 호길이가 뛸 수 있다 (Φ 불연속). 창고 통로 간격
   (열 간 6 m, `gen_warehouse_world.py:79`)에서는 드물지만 생성 맵이 만들 수 있다 — 생성기에서 경로 자기 근접 < 1 m 를
   거르거나 v2 에서 창 투영으로 바꾼다.
6. 목표 yaw 정렬을 플러그인의 결정론적 회전에 맡긴 것 — 비교군 간 공정성은 유지되지만 학습 지표에 정렬 시간이 빠진다.
7. 비교군 D 의 ONNX·관측 확장, GRU 은닉 상태 크기는 r1·r2 가 정해 onnx_io.md 에 올린다.
